## Finite witness and lifetime

Use the existing fault witness slot as a CLOSED discriminated union, not a larger
outer fault or cap. Retain unchanged ADR197 infrastructure witness semantics.
The new alternative has exactly schema,spawn,spawnCode,launchCode, where schema
is native-browser-launch-witness/v1. spawn is start-not-observed,
start-observed,spawn-error-observed,spawn-return-observed or unavailable.
spawnCode/launchCode are none,unavailable,unclassified or one of
EACCES,EPERM,ENOENT,EAGAIN,EMFILE,ENFILE,ENOMEM,EINVAL,ENOSYS,UNKNOWN.
spawnCode is none only without a spawn-error; unavailable accompanies unavailable
observation; an error has a recognized code or unclassified. Validate exact
state/code combinations in JS and Python. Non-error observed states require
spawnCode none; spawn-error-observed requires a whitelist code or unclassified;
unavailable requires spawnCode unavailable. launchCode projects only the exact
actual public launch rejection, never none, not an earlier or cleanup fault. The new union
alternative requires code === client-failure, stage === context.launch and
rpc === context.launch. These are the startup diagnostic's actual labels, not
the study capture's different launch stage. Observer
timeout snapshots are not borrowed for an unrelated generated deadline error.

For either code projection, require proxy-first types.isNativeError and inspect
ONLY its own code DATA descriptor against the closed whitelist. No immediate
Error.prototype requirement: Node's actual ErrnoException uses a custom prototype
and inherited constructor getter. Never read constructor, name, message, stack,
path, errno, syscall, raw values or coercion hooks. Genuine Error lookalikes with
finite codes remain only observations under the stated publisher assumption.
On the error channel a missing/accessor error descriptor, Proxy or non-NativeError
payload invalidates observation (spawn/spawnCode unavailable), without hooks.
A genuine NativeError with missing/accessor/non-string/unknown own code instead
retains spawn-error-observed with spawnCode unclassified. Any unsafe or nonnative
public launch rejection projects launchCode unclassified without inspection;
an internal projector failure yields unavailable, never a different original error.
[Exact Node error implementation](https://raw.githubusercontent.com/nodejs/node/v24.19.0/lib/internal/errors.js)

Use a private per-launch token, first-fault boolean and exact rejected-value
association. An observer helper may call the trusted action, but must return the
SAME original returned promise, not an async wrapper. Attach bounded native-then
side observation only after the existing safe-native-promise checks, before the
coordinator installs its own rejection observation. Bind and close the observer
before the same original failure is latched. A synchronous throw binds its exact
value then rethrows it unchanged. Unsafe returns are returned unchanged to the
existing quarantine, without hooks, assimilation or invented settlement.
Both passive native-then callbacks catch every observation failure and return
undefined without throwing; their derived promise cannot add an unhandled rejection.
Success closes observation and retains no error candidate. Falsy first values,
other errors, later cleanup and other attempts cannot borrow a witness.

logical private bytes BEFORE subscribing/dispatch, inside the existing32768 sum
alongside ADR197's320 reservation; this is not a measured heap claim. Retain at

state, no history. At most16 total notifications are inspected for this attempt;

start-not-observed is absence of this observation, not no-process proof;
