## Fixed diagnostic

Use a separate `native-extension-startup-dev-v1` namespace and owned output.
Run exactly two predetermined fresh persistent contexts sequentially: first
`serviceWorkers: 'block'`, matching ADR150, then `serviceWorkers: 'allow'`.
All other launch settings remain the reviewed installed Chrome, headless mode,
normal TLS, sandbox, fresh package-owned D:TEMP profile, selective removal of
`--disable-extensions`, and the owned extension-debugging flag. Close and drain
the first browser before starting the second. The second variant never rescues
an ADR150 input or replaces its failed outcome.

Neither variant navigates a public article, performs DNS, reads page content,
requests a provider, creates an embedding or opens application/account/database
interfaces. Keep the blank anchor only. Deny all ordinary host resolution with
`MAP * ~NOTFOUND`, disable proxy use within these contexts and install HTTP/HTTPS
request denial plus separate WebSocket closure before extension startup. Do not
permit consent, login, popup, download or unexpected worker handling. This is
an owned-browser restriction, not complete OS egress isolation.

Read only the six ORIGINAL fixed repository CODE paths used by ADR150 and copy
their byte-identical contents into a NEW owned staging directory, checked against
the immutable ADR150 freeze hashes. Do not read from old output. Do not inspect
old browser profiles, caches, cookies or captured bodies. The only old evidence
read is the fixed ADR150 freeze FILE770eb68ef044dadbb6ef0f2edf2c927b643480e7d06cbf496319b1cab9d457ec
and its fixed reviewed source/package CODE allowlist. No model/policy artifacts,

Record bounded controlled operation names before/after each awaited startup
operation: launch, blank-anchor inspection, HTTP/socket deny installation,

metadata. Targets are counts and own-extension equality booleans, not raw URLs.
Only if the real owned worker is available, call the frozen adapter's
`beginStudy` with its fixed32 metadata records, then `endStudy` without a read,
skip or observation. Never invoke the content reader or head-policy collector.
Observe actual native normal/incognito/focus metadata without inventing success.

An ordinary, genuinely settled startup API incompatibility ends that variant;
there is no retry, worker reconstruction or fallback transport. Unknown callback
or target, programming fault, source/resource violation, unproved physical
settlement, Job or inter-context barrier failure stops the WHOLE diagnostic.
Cleanup alone never converts these failures into a second-variant permission.
Native/client exceptions are projected only to finite safe

Both variants' actual outcomes are retained even if one startup path is
incompatible. Completed diagnostic accounting is not native compatibility or a
