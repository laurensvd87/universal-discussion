## General matching contract

An exact supported topic wins when available. Otherwise, choose the deepest
supported existing ancestor. Missing or rejected details do not require creation
of a new topic. Conflicting accepted branches coarsen to their common ancestor;
absent root evidence leaves the page ungrouped. Owner depth rules apply after
classification and preserve the supported path and stable IDs.

The ordinary rooted matcher already applies this contract to arbitrary numeric
membership heads, including named subjects. New composition tests pass actual
classification through ingestion preparation and public context projection.
They cover reptiles/animals, named `Games -> Rockstar -> GTA VI`, conflicting
publishers, misleading title cues, and `Technology -> Acme -> Tool X`. These
tests use invented artifacts and a simulated database envelope. A separate
retained Komodo vector pair exercises the real installed Animals matcher, but
replays transport text without an encoder and does not attest text/vector binding.

## Cached semantic candidate improvement

The consumed v3 cached index accepts lexical topic evidence but considers only
root categories when no accepted alias exists. The new explicit v4 successor
can consider supported intermediate common classes under its accepted root.
It reuses v3 validation, named-identity gates and fixed similarity/margin bounds;
no consumed source is edited and the default installed runtime is unchanged.

Tree position is not semantic type. In particular, GTA can have children while
remaining named. V4 therefore requires a separate exact bank-bound ordered
`semantic-category-kinds/v1` proposal covering every structural category. Every
ancestor on a semantic refinement path must be explicitly `common-class`.
Named and unknown meanings cannot acquire membership through cosine similarity;
a common-class child cannot bypass a named ancestor. Existing accepted lexical
paths remain unchanged, including supported named descendants and ancestors.
The ordinary numeric membership pipeline remains the general path for supported
named-parent fallback; this prototype is not an authoritative registry migration.

Body and paired similarity must each meet the inherited .8 threshold; the margin
against other roots remains .015. Require substantial body context and an
independently accepted root. Prune admitted ancestor nominations before comparing
maximal branches, then use their common ancestor when peers are within .015.
Owner grouping affects presentation only. Category meaning and policy hashes
bind the new index identity. No IDs, aliases, tree nodes or class meanings are
generated from a query or scoring gold.
