## Join actual public navigation facts

ADR172 proves four invented native-reader cases. Its synthetic route.fulfill
settlement must never be called public transport evidence. Before adapting the
four-case collector for the full hierarchy study, implement one bounded pure
public-article rendezvous that can join the real facts without changing the
production reader or the existing network/rights requirements.

Matcher owns only journey.mjs, test.mjs and README.md under
`spikes/topic-resolution/harness/experimental/native-specificity-public-journey-v1/`.
Root owns this decision. No IO, launch, browser connection, page request, model,
artifact, old input/result, provider or canonical access. Do not invoke any closed
entrypoint or modify frozen sources. Reuse pure logic only through reviewed code
or narrow source derivation; there is no new transport-only public cohort.

The trusted future collector supplies one opaque article-incarnation token, exact
Source URL, authenticated main frame, actual initial blank loader and one absolute
deadline established before setup. Validate the URL through unchanged inspectPageUrl
and require HTTPS, exact canonical syntax, no credentials/fragment and a supported
public-page shape. This is syntactic policy, not DNS/TLS/permission proof.

Success requires all of these independent facts for that incarnation:

1. The actual Page.navigate reply settled with the exact frame and a fresh loader,
   with no errorText or download.
2. Exact non-child main-frame commit at the selected URL.
3. The public network gate admitted one main response, joining its distinct Fetch
   request/response IDs to the same Network request, frame and response loader;
   exact URL,2xx HTML/XHTML, ordinary TLS and selected-public-peer checks already
   passed in that gate. Preserve these separate requirements, not fixture flags.
4. Loader-bound DOMContentLoaded.
5. Both actual request-continuation and response-continuation promises physically
   settled successfully for their respective admitted Fetch IDs. Count neither
   submission nor a wrapper that swallowed rejection as successful continuation.
6. Matching Network.loadingFinished for the admitted Network request ID. A
   continuation acknowledgement is not completed public transport.

Facts may arrive in any order after dispatch. No response, lifecycle event or
callback chooses the authoritative loader alone: the navigate reply is mandatory
and all candidates must agree with it and each other. Allow bounded quarantine of
transport completion/continuation facts before the response admission arrives,
but never publish before every identity agrees. Distinct Fetch IDs are allowed;
do not incorrectly require request-stage and response-stage IDs to be equal.
Retain at most one early candidate EACH for request continuation, response
continuation and loadingFinished, then rejoin all three to actual admitted IDs.
Validate tokens, IDs and plain descriptors before registering an observer.
Observe genuine original promises without arbitrary then hooks, immediately
handling rejection; no timeout may free their physical work or imply success.
Successful continuation observers return undefined, never the native ACK payload:
forwarding a fulfilled object could trigger a later-added then getter through
Promise resolution. Preserve the original rejection object and synchronous error.
If registration refuses an already-started structurally safe genuine promise,
attach only rejection-handling cleanup with both intrinsic handlers returning
undefined; it registers no journey fact, event or authority. Unsafe promises
cannot be safely observed here and must already belong to the outer physical
tracker. The tracker owns every started native operation regardless of refusal.

Use the existing main-response evidence shape/predicates as the trusted network
owner's input, not a proof of publisher rights minted by this module. The later
collector must use the reviewed public gate and actual CDP observations. Keep
HTTP identifiers explicitly not directly correlated with Chrome documentId.
Native locate/read/attest and before/after document-targeted rights snapshots
remain mandatory outside this rendezvous.

## Fail closed and retain article ownership

Preserve ADR172's exact prepared initial-blank lifecycle replay behavior,
bounded ignored-lifecycle enum, agreement/duplicate/contradiction rules and
late-callback refusal after resolution and retirement. Use the same20s absolute
lease from before the first setup RPC; no arrival, retry or report resets it.
The module has no timer or cancellation authority; timeout is not settlement.

Duplicate, mismatched, child-frame, replaced-loader, redirect, download, malformed,
unsupported security/identity or unknown callbacks fail closed. Do not classify
an unknown failure as an unavailable page. A matching loadingFailed yields only
a finite terminal network-failure classification; the later collector's fixed
failure taxonomy decides whether that is a normal unavailable row or a fatal
study fault. No retry, partial publication or fabricated rights follows.

Every callback checks incarnation/deadline and the outer trusted guard, including
checks after potentially time-consuming guards. Preserve a first finite failure
and promise rejection without raw arbitrary strings/errors/URLs in reports.
Late original callbacks cannot affect another article. Retirement requires a
resolved journey or finite failed terminal outcome, never fake readiness for an
unavailable page. Failed retirement is cleanup-only and cannot publish input.
The future owner's exact target destruction, tombstones,
complete census and physical drain still control slot reuse. This helper grants
none of those capabilities.
Any late contradiction latches a sticky fault and trips the owner guard, even
after the readiness promise has fulfilled; an already fulfilled promise is not
revoked. Require a synchronous current-incarnation/completion check immediately
before and after every native/rights await and immediately before row publication.

Bound each journey to4096 events, identity strings160 ASCII units, URLs2048,
one response, one pending candidate per fact and32KiB accounted private state.
This accounts bounded stored payload/record state, not browser, closure or native
allocation. Physical promises and operations remain the outer owner's charges.
Strict plain descriptors/dense bounded arrays reject proxies/accessors before
hooks; all numbers are finite and appropriately bounded. A finite fixed report
contains fact-presence/arrival counts, agreement booleans, lifecycle categories
and one failure code, at most8KiB UTF8. No raw native IDs, headers, peer addresses,
URL/hash, page text or arbitrary nested values escape through that report.
