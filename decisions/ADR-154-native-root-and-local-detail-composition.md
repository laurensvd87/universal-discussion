# ADR154 Native root and local detail composition

Date: 2026-10-20. Status: implemented and independently reviewed as an
unregistered numerical composition. No actual artifact or model execution.

## Decision

Implement a pure experimental composition of the existing native root-rank
candidate and local-exemplar detail policy. A unique accepted independent root
is mandatory. Detail can extend that root to GTA or Koalas, return a common
ancestor for plausible siblings, or retain the root when unsupported. It cannot
rescue root abstention, switch roots or force a nearest leaf. This supplies the
numerical candidate for a later fresh child/STOP/sibling/outside study, not a
quality result, native attestation or live assignment policy.

Use new three-file namespace
`apps/local-service/src/domain/experimental/native-root-local-detail-transfer-v1/`
with adapter, invented geometric tests and README. No IO, fitting, artifact
loading, classifier registration, browser/provider work or canonical mutation.
Keep all closed code, model artifacts and results unchanged.

## Separate input and policy identities

Compile the unchanged native root candidate DTO and unchanged local-evidence
artifact independently. Detail has its own paired body/title fusion definition;
its encoder must equal the root encoder and its derived representation identity
must equal the original local artifact. Detail roots are an explicit nonempty
subset of approved native root IDs. Reject foreign roots or an approved root
masquerading as a detail child. Validate all identities and finite capacities
before scoring. Original detail construction and actual native target builder
must remain distinct and separately recorded; do not rewrite an artifact or
create a fake fit receipt to make a namespace check pass.

Classification accepts exactly the existing native-root input, with no separate
detail vector, supplied path or caller score. Copy the same descriptor-checked
raw384D body/title pair privately, preserving binary64 and signed zero, and call
the native root scorer first. Root abstention or a root outside the detail subset
performs zero detail scoring/fusion work. For a supported accepted root, apply
the independent detail fusion to the same private pair. Zero fusion retains root.

The original local classifier checks its artifact's numerical policy namespace.
Therefore construct a private numeric query with synthetic numerical IDs, its
original representation and original artifact input-construction hash. Bind that
query to root transfer identity, native Source-input hash, root semantic witness,
original detail artifact identity and exact derived-vector binary64 hash. Label
it explicitly as an internal numerical-policy namespace, not a native Source,
version, capture builder, training attestation or current-state proof. Preserve
the actual native witness and its target construction hash unchanged in output;
never return the local classifier's synthetic source identity as that witness.
The transfer identity binds both independent fusion definitions and original
artifacts, actual native target profile and explicit unvalidated transfer status.

The final composite decision has its own versioned semantic-witness hash binding
the composition transfer hash, original root semantic-witness hash, native
Source-input hash, original detail artifact/representation, exact derived-vector
bits, actual local outcome/path or its hash, and final supported path/reason.
Never reuse the root-only semantic hash as authentication of a deeper decision.
Synthetic query IDs are fixed-prefix digests within160 characters and never
reuse native IDs or claim training-source provenance. Hashes bind supplied data;
they are not native or canonical attestations.

Only an accepted same-root local path may refine the independent root. Existing
local STOP/negative/group/MAX-view/common-ancestor semantics remain authoritative
inside detail. Cross-root ambiguity, conflicts and unresolved detail retain root;
capacity or malformed-input errors remain errors rather than fallback evidence.

## Limits and checks

At most16 roots,128 detail nodes and512 local references. Refuse work above the
existing four-million-unit local preflight bound before query scoring. At most
528 root/detail dot products and202,752 coordinate products,64 root rank
comparisons and6,144 scoped fusion coordinate visits. Counters do not measure
all copying, validation, hashing, encoding or whole-application latency.

Invented geometric checks must cover separate fusion weights and encoder/hash
mismatch, same-root GTA/Koala detail, sibling common ancestor, direct parent STOP,
unknown child, root abstention and unsupported-root zero detail work, cross-root
conflict, zero fusion, hostile getters/proxies/mutation, signed zero and exact
caps. Native witness preservation and explicit synthetic policy namespace require
regressions. All flags retain experimental/unvalidated/no-production/no-assignment
status. Real child/OOD quality, actual rights/text-to-vector provenance, fresh
locked validation and canonical/crawler/UI integration remain separate gates.

Root owns this decision; fixture owns only the three new files. Independent Trust
design review precedes implementation and full source review precedes any later
study. This decision authorizes neither data/model execution nor live activation.

## Checks

Root and Trust each pass all12 invented geometric tests with external capabilities
denied and128MiB heap. Checks include independently recomputing the final semantic
binding and hitting the exact128-node/512-reference/16-root numeric caps. These
establish composition mechanics, not actual native capture, semantic quality or
application latency. Exact source hashes and review scope are recorded in
`apps/local-service/data/native-root-local-detail-transfer-review-20261020.json`.
