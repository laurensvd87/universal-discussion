# ADR-143: Current-producer transfer gate for fast hierarchical matching

Date: 2026-10-20. Status: prospective design; implementation and all execution
remain gated on review. No runtime, canonical, provider or owner-account action.

## Why another gate is needed

ADR142 is closed. Its small prospective root feasibility gate passed:29 correct
accepted roots, zero wrong and3 abstentions on32 new Wikipedia pages. The four
specificity anchors yield one exact GTA path and3 safe broader paths. These are
not representative-web,98%-precision, unknown-root or general-child guarantees.
Its selected input is a Wikipedia prose-lead builder, not the application's
browser body. Neither reuse of E5 nor matching fusion hashes proves input parity.

Even the stored current-static training view applies metadata pruning before the
static extractor. Live crawler and browser producers have distinct provenance.
The new gate must expose that transfer rather than relabel any old artifact or
use the consumed final32 to select a different candidate. Keep ADR142 and all
earlier code, cohorts, outcomes and receipts immutable.

## Fixed optimization, then fresh articles

Reuse only the exact eligible127 TRAIN and48 CAL from ADR142, current-static
vectors only. Their reuse is optimization, not new independence. No new training
encoding, old final body/vector/outcome read or label extension. Do not retune
closed models/detail heads or add hyperparameter search; the three NEW root fits
below are predeclared.
Fit three root-only models at lambda .1 and body weights .5/.75/.25. Select using
CAL accepted-correct count, then raw-correct count, then that fixed weight order.
Use unchanged pooled observed score/gap cuts: at least20 accepted independent
CAL groups and zero accepted errors. All models share precisely the same cohort.
This gate is ROOT ONLY. Defer C detail, owner display projections and child
decisions so the transfer question does not become another hierarchy retuning.

Before any final capture, seal32 new public article identities, two per existing
root, preferably at least24 non-Wikipedia articles over at least8 such hosts and
several languages. Root and independent review must confirm feasible coverage or
revise this prospective design before freeze, never silently weaken it later.
Exclude old real128, ADR141's112 candidate entities, prior curated/DEV cases and
obvious aliases. Primary-page opens inform manual labels, not model scores.
Keep root-positive prefixes separate from any genuinely known terminal scope;
unknown descendants are not negatives. No forced child annotation is needed.

Persist selection/model/policy, producer-profile and training-cohort identities
before opening the32 final inputs. Every article is one independent group even
when two producers observe it. Never claim64 independent test articles.

## Explicit producer and policy boundaries

The experiment declares three distinct builder identities: stored pruned static
training input, current static target input and the exact current browser reader.
Bind each extractor/version/source and all preprocessing into the producer profile.
Shared384-dimensional E5 fusion geometry does not erase this distinction. The
SAME selected model, fusion weight and numeric score/gap cuts apply to both target
producers. Their profiles are provenance, not separately fitted thresholds. A new
thin trusted wrapper binds the training builder, selected artifacts and both
declared target profiles; internally it retains the original scorer's policy
identity and externally binds the actual producer/input/document witness. Never
forge a browser witness using the training construction hash. The wrapper rejects
undeclared producers and mismatched witnesses. This is a transfer test, not a
claim that browser and static bodies must be byte-identical.

Collect bounded title/body once per producer/article, with exact text/title,
URL, extractor, document/navigation and source-construction identities. Browser
capture must run the pinned real reader in a fresh isolated profile, never the
owner profile, extension, pairing or credentials. Missing regions, delayed content,
identity mismatch, unsupported input and refusal stay explicit. No alternate
builder, title-only rescue or delayed retry after a failed selected observation.
Observe ONCE at the matching main-frame loader's DOMContentLoaded plus2 seconds,
within an absolute20-second per-article navigation/observation lease. DCL after
18 seconds does not extend that lease to obtain the extra2 seconds. An old or
initial about:blank event cannot satisfy it. No later mutation is recaptured.

Keep public-fetch DNS/TLS, byte/decompression/ratio/MIME/charset, robots/TDM,
noindex and known-repair bounds. Separate rights/transport eligibility from static
EXTRACTION availability. Do not retain browser input for an article whose static
rights/transport eligibility is unknown or refused; both producers remain
unavailable in that article's denominator. Static missing-region/insufficient-text
after completed rights checks can leave the browser eligible, never a parsing
failure that prevented checking rights. Browser navigation must intercept and
validate its own matching main-document response: exact final URL, successful
status, bounded X-Robots/TDM headers and no reservation/blocked directive. Validate
DOM directives at the fixed snapshot; bind frame/loader/navigation incarnation.
Request-only interception is not sufficient for this new guarantee.

Each fixed browser batch independently checks robots and TDM documents for every
applicable literal page origin before navigation, enforcing the exact URL and
crawl delay. Cache only within that batch, never assert freshness across batches.
Limit those policy requests to5 seconds each (stricter than the original15s cap),
at most8 requests for4 distinct origins. Their40 seconds of request durations is
NOT the elapsed policy-phase budget: robots pacing and crawl delays still apply.
Bound the complete policy phase to60 seconds; inability to honor a required delay
within that budget leaves that origin explicitly unavailable, never shortens the
delay or grants navigation. All remain under the same absolute Job wall.
Rights refusal is not a wrong semantic label or out-of-taxonomy article.

Public-fetch DNS pinning does NOT establish Chrome DNS pinning or complete SSRF
isolation. The browser scope is fixed reviewed trusted public hosts over ordinary
certificate-validated HTTPS, strict literal request allowlists, a fresh unpaired
profile and no credentials. Browser-specific remote-address/response checks need
review; do not claim they prevent every connection or all Chrome/OS background
egress. No localhost/private-host or broad wildcard allowance, certificate bypass,
authenticated profile, consent/login automation or expanded provider authority.

The new collector may account for per-article unavailable results prospectively,
without retry or URL replacement. All32 rows remain in each producer's denominator.
Resource, abort, absolute Job-deadline, source-identity or integrity failures stop
the phase and preserve evidence; they are not usable-input refusals. Ordinary
per-article navigation/observation timeout, policy refusal, missing region or
unsupported input are explicit unavailable states, never retried; all other
unhandled transport failures stop. Exact typed unavailable reasons must be frozen
and tested before collection, not inferred from arbitrary strings. Valid bounded
reader output that contains noisy, generic or misleading text still counts as an
evaluable input: a wrong root counts AGAINST that producer. No post-score manual
off-entity/body-quality exclusion or cohort repair. No origin-policy
failure grants page fetch/retention. Cache known refusal only within a batch rather
than repeatedly trying the same failed policy. Collector details, request budgets,
literal page/script host allowlists and phase timing require independent review
and a new freeze before any network operation.

## Acceptance and reporting

Evaluate static and browser separately, each over all32 articles. Predeclare a
small feasibility gate per producer: at least24 accepted, zero wrong accepted and
at least one accepted article per root. Report available/refused/missing counts,
per-root/language/host outcomes, conditional-on-available figures, paired agreement
and producer-specific errors. Do not combine their successes, drop unavailable
rows or choose whichever producer worked after seeing the final.

No detail classifier or child prediction runs in this root-only gate. Optional
terminal annotations do not change that scope. Known roots and public articles
do not validate OOD/unknown-child rejection.
Small purposive cohorts cannot establish population precision. No post-test
retuning, new thresholds, case replacement or repeating a failed phase.

Record extraction, local encoding and classification separately from application
queue/SQL/UI time. A scan-free production admission path and real native-context
integration still require their own review and measurements; a fast classifier
beside the existing exhaustive scan does not satisfy the product requirement.

## Browser compatibility proof before consuming the new final

First review the new response/directive/navigation instrumentation with pure
fixtures and a separately versioned fixed four-page capture of ALREADY-consumed
public DEV controls. No E5, classifier, threshold selection or body-quality tuning
on those controls. Freeze their exact identities, sources and resource schedule
before that single compatibility attempt. Only a successful reviewed compatibility
proof permits the fresh32 final label/source/profile freeze and target collection.
Failure preserves evidence and stops; never split or retry the same attempt.

## Bounded implementation and execution

New files/namespaces only. Reuse reviewed pure arithmetic without editing closed
sources. A builder-scoped scorer privately compiles validated artifacts and accepts
exact bounded Source/input/incarnation witnesses plus body/title vectors. Its
supported path and identities are experimental presentation evidence, not Source,
canonical-write, native-document or provider authority. Owner display cuts stay
separate from semantic identity. Existing posts/destinations are never moved.

No training E5 calls. At most128 final encodes (title/body for two producers over
32 articles), with no reuse across unequal titles or inputs. Freeze exact source,
metadata, assets, reused input bytes and work ceilings. Hash and parse the same
initial buffers, fresh-read before publication; fixed allowlists exclude old final
inputs and owner/private paths. Exclusive markers/results prohibit automatic replay.

Retain the reviewed one-thread owned Win32 Job/assignment handshake,1536MiB
RSS/private/Job-commit limit,1GiB host physical/commit reserve,C768MiB/D512MiB free,
fresh retained D TEMP,180s model phases and verified own-tree drain. Browser
batches use a prospectively fixed EIGHT batches of FOUR articles, never adaptive
splitting. Each180s Job includes startup, at most60s complete origin-policy phase
(including pacing), at most80s navigation/observation leases, and at most40s total
startup/overhead/source-check/close/drain allowance. Explicit tighter child-active
and final-drain guards must fit the complete180s bound before
freeze; compliance is observed, not inferred. The earlier four-page DEV browser
peaked1.309GB, so eight-page memory safety is not assumed. Static collection uses
a separately reviewed absolute360s bound.
No model download, provider request, service/crawler interruption, canonical DB
write or credential operation follows from this design. Root and independent
reviews, pure tests and the new source/label freeze precede every actual run.

## Pre-freeze browser scope correction from independent code review

No final input has been collected and no new model has been fitted. Review found
that host allowlisting alone does not prove URL-specific robots/TDM/response
authorization for external Script/XHR/Fetch/Other resources. To close that gap
without introducing an untested resource scheduler, the final prototype is
restricted to the exact current Document request. All external subresources,
including scripts/stylesheets and data requests, are blocked; inline scripts
may still execute. Own-document response/DOM/frame/loader/TLS/public-address
checks, one DCL+2s observation,20s lease and all32 denominators remain unchanged.

The target construction recipe explicitly binds
restricted-single-document-dom-reader/v1 and
ordinaryDynamicBrowserProducerValidated:false. The browser-current technical
producer ID denotes the pinned current reader under THAT restricted observation
contract, not ordinary user-page loading. Report its quality separately from the
actual current-static extractor; passing both numeric gates does NOT validate
ordinary dynamic-browser transfer or authorize a browser/application cutover.
Future full resource-policy instrumentation requires a separate reviewed version.
Closed DEV results remain historical compatibility evidence, not an equivalence
or quality proof for this narrower final producer; do not replay them.
