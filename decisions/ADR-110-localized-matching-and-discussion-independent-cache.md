# ADR-110: Localized matching and discussion-independent cache

Date: 2026-10-13
Status: Owner-approved; implemented, independently reviewed and active

## Request and boundaries

The owner explicitly requests no complete grouping rebuild when someone posts
or visits an existing page, and localized regrouping around a new/changed page.
Posts change Discussion, not the semantic evidence used to group pages. This
approval covers local mathematical reuse/background preparation, not provider
inference, another browser model, capture expansion, durable derived vectors,
DDL/migration, deployment, historical rewriting or relaxed matching rules.

Canonical adaptive grouping and the read-only Ridge alternate view are distinct.
Both keep their exact existing thresholds, qualification, support/duplicate
rules, deterministic ties, manual pins, sticky retention and routing authority.
Reusing a partition is never permission to reuse a discussion response/version.

## Decision

### Matching identity and current responses

Public grouping reuse is keyed by generation and the exact Source geometry,
qualification/eligibility fields and link methods, not canonical revision.
Normalized read-only workers hash current public Source/embedding/link bytes
without loading posts or copying decoded vectors. Receipt fields, messages,
authors and ordinary canonical revisions are not grouping inputs. Provisional
Topic routing has a separate identity; manual destination authority also
participates in related-ranking identity. Limits/artifact instances remain
separate. Strict source/schema/accessor/proxy checks prevent manufactured hits.

Unchanged mathematical evidence reuses vector/ranking preparation and groups.
Current Source assignments, Topic metadata, canonical posts, actor labels,
generation/revision, pairing/app session and final response proofs are still
read/revalidated. Cache contents never become a response-authority watermark.
Cross-process writes are detected by current database identity, not by a
writer-local notification or a guessed version shortcut.

### Exact affected neighborhoods

A private bounded dependency graph retains unchanged edges. New/replaced
geometry compares only changed evidence with the current inventory. Deletion
removes incident edges; components are recomputed, not permanently unioned.
The whole affected component is replanned by the original algorithm; unchanged
components reuse mathematical results. A bridge can join multiple components,
and an update/deletion can split one. No greedy nearest-Topic attachment or
approximate candidate truncation is introduced.

Ridge uses the fixed admission floor minus a conservative 1e-10 connectivity
margin. That margin changes only which work is recomputed, never admission.
The original coarse/refinement algorithm decides membership and ties with the
original transform arithmetic. Exact duplicates retain all Source IDs but do
not manufacture independent evidence. Transforms are memoized per immutable
artifact/generation, with compact raw-coordinate digests and exact raw-value
collision checks, including signed zero.

Canonical adaptive grouping uses conservative floor-minus-competing-margin
connectivity (0.86 minus 1e-10), because a neighboring outsider below 0.90 can
veto a merge. All members of each current Topic are also connected, including
deliberately incoherent manual pins. Component identity includes current
Topic/link method, URL duplicate-support and per-Source retained-tight state.
The original planner runs on complete affected components; original decision
phase/initial-group order is restored. Global stable-Topic reconciliation and
whole-subthread lineage routing still run through the existing guarded commit.
Sparse/decorated legacy vectors use the original path rather than being
reinterpreted. Trusted remaining-time arguments can only shorten the original
ten-second budget, never extend it.

### Background preparation and resources

Normal CLI explicitly enables the reviewed optimization; fixture/factory
defaults keep the old mathematical algorithm for differential checks. One
startup preparation and debounced committed matching-input hints use the
existing isolated projection worker. One flight/one dirty flag, not a queue
per visitor/message; failure does not spin or replay commands. Notifications
contain only version and ignore posts, receipts and provisional routing.
Internal warmMatching has no HTTP/public read route and returns no page,
actor, vector, post or account DTO. Core HTTP/auth/deadline fences are unchanged.

Caches are disposable RAM only. Ridge retained limits are 32 MiB transforms,
32 MiB graph and 8 MiB component results; adaptive graph/results have 32/8 MiB
limits. Old-plus-next graph preparation may transiently approach 64 MiB, plus
input/oracle/cache scratch; the existing 256/32 MiB worker heap fence remains.
No claim of a 32 MiB total process peak is made. Deleted/excluded obsolete
geometry/results are purged; shared geometry may remain only for surviving
eligible Sources. Generation/artifact change and failures clear reuse state.
Cache overflow falls back to the original complete bounded algorithm, never
publishes a partial/approximate plan. Cold startup and large connected affected
components still cost substantial work; RAM reuse does not survive a restart.
Metadata/hash validation is still linear work on a changed repository revision.
