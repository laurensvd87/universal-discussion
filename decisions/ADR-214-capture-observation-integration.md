# ADR 214 Capture observation integration and bounded failure output

Date: 2026-10-24
Status: SOURCE experiment design accepted by Root Native and Trust; candidate implementation in progress

## Purpose

Integrate the ADR213 first-context observation into an isolated collector
candidate so the next hierarchy-quality study can distinguish the six existing
terminal-navigation refusals. The candidate must preserve collection policy,
the exact original failure, existing non-null diagnostics and the32768-byte
aggregate limit. A diagnostic that merely hides a failing integration fixture
is not an acceptable result.

The ADR212 attempt is closed with failure. Its last RPC does not identify the
cause. All consumed v1-v19 source, source maps, package files and outputs remain
immutable. This experiment neither retries that attempt nor authorizes another
actual phase, model inference, database change or live activation.

## One context slot and actual article ownership

Port the ADR213 scalar command logic into the existing batch navigation-call
function. Do not retain both old and new holders, or add a second callable
holder. Remove the old attempted/original/candidate/helper-binding holder.

The control inventory is the five ADR213 cells, the current article's fresh
primitive Symbol, its ordinal and one module bridge reference to that same
existing callable: eight cells plus one callable, within128 control bytes.
Encode transport state in the existing phase scalar rather than adding a ninth
cell. The remaining128 bytes retain the authored context view and its declared
scalar construction scratch. Keep the full256 reservation in every state.
This is logical metadata accounting, not a bound on V8 frames or arbitrary
externally owned error graphs.

Mint the Symbol only for the actual current article while the context slot is
empty. Every normal navigation claim must prove the exact current state, actual
helper identity, original ordinal and unique original ledger slot. A terminal
claim must additionally pass the existing private terminal session/token/page,
revocation, close-issued and retirement predicates. Its ledger may contain the
actual helper or the legitimately paired zero tombstone after an unavailable
article released that helper. Never keep or resurrect a helper just to obtain
diagnostic identity. Symbol equality alone is not native provenance.

At each of the six existing refusal branches, observe only fixed literals
describing that branch. Preserve existing descriptor checks, IDs, rooted-child
validation, event counts and short-circuit priority. Main-frame refusal precedes
missing-parent refusal; detached-main refusal precedes main-object equality.
Diagnostic observation cannot replace the exact error object or throw a new
one into the failure path.

The first global `remember` latch synchronously consumes primary or cleanup
selection before any infrastructure, network, owner or coordinator observation
reader can throw or reenter. An unrelated first error consumes the slot too.
Use presence and `Object.is`, not truthiness or error-property attribution.
Later calls, cleanup or another article cannot lend context. Replace the old
pending-candidate release veto with the equivalent consumed/claimed-slot veto.

## Private authored diagnostics and public validation

The private first-fault path may directly adopt its own frozen authored context
view. Build and freeze the outer diagnostic only after its allocation is funded.
Do not run the public adversarial projector on that graph merely to copy it.
`captureFailureDiagnostic()` may return the same immutable private graph; no
fresh-copy contract was found. Caller-created frozen DTOs remain untrusted.

Preserve the public projector as a strict, detached, descriptor-safe closed
validator. Its existing navigation schema is unchanged. Add only the terminal
closed union in the existing `navigationAccountingWitness` field. Correlation
with the exact terminal failure family/code and exclusion of unrelated witnesses
remain mandatory. Public projection does not mint a private emission capability.

A cleanup observation can replace the outer DTO once, without mutating an
already-issued graph. Charge both outer graphs while their lifetimes overlap.
The same rule applies to reentrant readers and already-issued caller views;
clearing a holder is not evidence that another owner released its view.

## One sticky transport reservation

The actual v19 driver clones the graph through its public projector, stringifies
it, parses and stringifies the text again, then constructs an envelope and a
Buffer. Returning an authored graph alone does not bound this overlap.

The candidate private path therefore obtains one conservative8192-byte transport
reservation through pure aggregate preflight **before its first outer diagnostic
allocation**, not only immediately before emission. The charge includes the
authored graph, cleanup-graph overlap, any remaining bounded projection scratch,
UTF16 JSON text, envelope construction and the final UTF8 Buffer. Its complete
live-allocation inventory must be reviewed against the actual code. The holder256
and every live registry remain charged alongside it;8192 is not an increased
aggregate ceiling.

Reserve once and keep that charge through owned Node exit. Do not refund it on
serialization return, observer release, emitter return, a false write return,
or a Promise returned by a mistaken emitter. The actual emitter calls
`process.stderr.write(bytes)`, whose synchronous return does not prove physical
consumption. Node's writable contract permits buffering and identifies a
separate completion callback; see the [Node stream documentation](https://nodejs.org/download/release/v24.20.0/docs/api/stream.html).
No new callback, timer, completion wait or retry is needed merely to reclaim
this failure-only reservation.

The private actual composition serializes its authored graph once and invokes
the fixed original emitter once. It does not parse its own authored canonical
text, accept a caller DTO as private provenance or expose a public trusted-mode
boolean. The existing public driver boundary keeps validating arbitrary
diagnostic text as before. The private path requires a separately owned,
source-authenticated composition, not matching hashes or error properties.

If the reservation cannot be obtained, consume the attempt, preserve the original
failure and produce no outer graph or output allocation from that path. Even a
`capture:null` envelope costs memory and is not free at zero headroom. The later
actual driver/execute composition must share this private attempted/denied/owned
decision so its outer catch cannot append an unfunded generic stderr suffix.
The candidate must not be admitted to an actual phase until that composition is
reviewed; the frozen execute module is not changed by this experiment.

Normal completion clears the bridge before releasing the batch. A failed batch
retained by that bridge remains fully accounted, not charged as just an8-byte
pointer. A released/consumed bridge cannot reopen a slot. Reentrant emission
cannot allocate a second report or Buffer; cleanup/release cannot erase the
sticky charge. Pure preflight must not call a guard, clock, native operator or
allocate an unreserved snapshot/serialization. A numeric owner-accounting reader
may be added in the new owner candidate only with parity proof against every
original field charge; it cannot erase records or weaken lifecycle checks.

The reviewed owner-accounting experiment reuses the existing accounting function
as the callback of captured native Map and Set `forEach` originals. It adds one
numeric accumulator cell and charges an explicit8 bytes in every state. Its
numeric reader and snapshot must equal the frozen original accounting **plus8**,
including after release; the original128+8192+512 base and every Set, Map, field
and pending charge remain intact. Zero arguments is the sole public recomputation
form. Callback mode requires exactly three arguments and the exact private
collection before inspecting an entry. There must be no external callout or
reentry while that accumulator is in use. Literal-field accounting needs an
inventory of all twelve actual constructor/mutation keys and differential tests
of partial and complete lifecycle traces; omitted fields must fail the proof.

## Required executable evidence

Run the complete original148 capture reports and26 driver reports as authenticated
references. Run their behavioral assertions against the candidate as well.
Private-layout introspection scaffolds must be adapted explicitly: old holder
names cannot remain as dead compatibility storage merely to satisfy a regex.
Preserve the semantic obligations and report each scaffold adaptation.

The original exact32768/32769 fixtures exercise journey/accounting, not driver
transport. They must still preserve the same non-null journey report at32768,
one failure notification, the exact original error and the original unavailable
behavior at32769. A separate zero-headroom transport test may require no output;
it cannot change those assertions. Existing full-integration journey, timer,
infrastructure, operation, network, owner-navigation and main-navigation witness
fixtures must remain non-null wherever they were non-null before. Measure the
honest aggregate when acquiring8192 in these fixtures; failure to fit is a real
integration failure requiring an allocation fix, not a diagnostic-null waiver.

Additional candidate tests must cover:

- All six actual terminal branches, their precedence, exact current article and
  unique ledger binding, released unavailable tombstones, foreign/duplicate
  helpers, stale ordinals, falsy originals, competing faults and cleanup-first.
- Reentrant observation readers, primary selection, cleanup and release; no
  borrowed observation, repeated view construction or diagnostic resurrection.
- All closed-union wire combinations and the unchanged700/900/1024-byte ceilings.
- Numeric-accounting parity and combined registry/transport boundary cases.
- A deferred emitter that retains its first Buffer after return, false returns,
  thrown and falsy emitter failures, unsafe Promise/thenable returns, repeated
  outer catches and late callbacks. The reservation never refunds or retries.
- Zero-hook hostile public DTOs and unchanged public text-boundary behavior.

Use only invented browser/callback capabilities under the existing offline
capability guard. No actual browser, DNS, model, assets, provider, raw captured
body, live database, service restart or crawler action is part of these tests.

## Subsequent hierarchy work

Acceptance of this candidate would repair the observation path, not establish
hierarchy quality. A fresh complete source closure, independent review, resource
checks and separately admitted actual phases remain necessary before a selected
matcher can be validated. Canonical hierarchy persistence, deepest-confident
assignment, owner-wide/per-topic specificity, stable discussions and rendered UI
plus crawler-concurrency/latency verification remain part of the original goal.
