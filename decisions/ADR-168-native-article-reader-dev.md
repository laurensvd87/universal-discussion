# ADR168 Native article reader diagnostic

Date: 2026-10-20. Status: independently accepted for source-only implementation
after the continuity, retirement and identity clarifications below. No native
execution, public article capture, E5, inference or production change.

## Required result

After ADR166's successful blank-browser startup, exercise the actual production
reader, URL policy and native document-rights adapter on four source-pinned,
invented articles in an isolated owned Chrome profile. Prove article creation,
document targeting, extraction, refusal and normal owned-process drain before
spending the new168-case public panel on another untested capture path.

This diagnostic establishes native article plumbing only. Synthetic delivery is
not public TLS/peer validation or publisher permission. It neither scores a
semantic model nor replaces the held-out root/child/STOP/outside quality study.
That study remains a separate prospective protocol with fixed TRAIN/CAL/TEST,
original root model/cuts, native producer identities and all original cases.

## Fixed transport and fixtures

Use only the existing production policy's exact
`http://127.0.0.1:4173/background-fixture/` scope. Do not modify the production
policy or create a test-domain exception. Four literal fixture URLs and their
HTML bytes are frozen source, not user/crawler content or copied articles.

Install ONE context-level route owner before Page creation. Use route.fulfill
with fixed status, headers and source-pinned body bytes; the pinned Chromium
implementation sends request-stage Fetch.fulfillRequest with that route's own
interception ID. Do not install a competing explicit Fetch.enable or second HTTP
interceptor. Only the four exact declared fixture document requests may qualify.
Synchronously consume each one-use token BEFORE any await: authenticate the exact
Request, Page and mainFrame, GET, navigation/document resource type, no redirect,
exact URL and live article lease. A duplicate or subframe request cannot replace
the admitted identity. Abort every other request; handler failures remain fatal.
No path/response/json/fetch/continue/fallback/unroute option, listening server,
DNS, HTTP client, public network or external resource. Keep WebSocket denial
separate. Fulfill/abort settlement stays physically charged; actual response,
frame/loader/document observations and exact hashes prove completion, not merely
the fulfill acknowledgement. The synthetic response path
must stay separate from all public TLS, resolved-address and peer validators.
Any request ambiguity, redirect, subframe or unexpected target is fatal.

The four declared cases are:

1. A semantic article region with navigation, hidden and form text that must be
   excluded. Assert the exact expected production body and title hashes.
2. A supported fallback region with empty raw title. Assert the actual extractor
   version, exact body and hostname-effective-title rule without title rescue.
3. Robots/TDM-denied document head. Refuse before article text read; account for
   this unavailable row without a fabricated capture or accepted rights claim.
4. Separate subchecks on the final fixture: first prove baseline same-document
   read/attest success; then mutate the actual head to a fixed declared deny,
   keeping its native document ID unchanged. The post-read rights recheck must
   refuse with ZERO successful retained-input publication. Separately request a
   fixed syntactically valid but nonmatching document ID and prove refusal with
   no fallback to current-document execution/read. Same-document attestation alone
   is not a head-mutation check, and one refusal cannot stand for both subchecks.

Retain actual Chrome tab/frame/document IDs only in bounded diagnostic RAM.
Persist only fixed case IDs, exact invented expected/actual hashes, finite
outcomes, bounded operation/callback evidence and sanitized cleanup metadata.
Never persist article text, DOM or arbitrary native errors. No model is loaded.

## Article ownership and callbacks

Preserve ADR166's exact anchor, two observed browser_ui tuples, worker identity,
bounded callbacks, census and normal physical-drain requirements. Its original
registry rejects a second blank Page and cannot be reused unchanged as an article
registry. A separately reviewed article-owner policy is required.

Before exactly one newPage call, reserve one provisional article slot. Callbacks
may quarantine only one initial about:blank Page in the authenticated anchor's
context during that operation. Quarantine confers no navigation, read, permission
or source authority. Authenticate the actual Page handle returned by newPage
through its own CDP session and Target.getTargetInfo without a caller-supplied
target ID. It must bind the same quarantined identity and exact context. Reject
all extra, replaced, ambiguous or unmatched page identities and dispose on timeout.
Do not choose whichever callback happened first as an authenticated article.

After authentication, allow only this Page's declared blank-to-fixture main-frame
navigation with the exact frame/loader/document journey. Actual native foreground,
permission and nonincognito/normal-window checks remain required before and after
read and attestation. Unknown workers, popups, dialogs, downloads, replacement
targets and unexpected navigation remain fatal. CDP frame/loader identity and
Chrome scripting document identity are proved separately and bracketed on the
same owned Page/frame/URL; never equate their IDs across protocols.

During declared owned-page retirement, allow only that exact target's expected
destroy/detach events and turn them into tombstones. Late read/input/navigation,
unknown IDs or replacements remain fatal. A retiring target never regains read
or navigation authority, including while callbacks are still draining.

Retain tombstones through whole-browser drain. Four cases plus anchor, two UI
targets and one extension worker fit within32 targets; do not expand target or
callback capacity. No browser/context reuse after an unsettled operation. The
diagnostic ends only after normal callback, physical process and owned-Job drain;
emergency termination is failure, not a passing cleanup path.

Four article lifecycles exceed the blank diagnostic's32 stored summary rows.
Prospectively change ONLY observation storage: retain the first32 valid sanitized
summaries, exact counts for a fixed literal callback enum, total count and dropped
summary count, with retained+dropped=total. Validate every callback before deciding
whether its valid summary fits. Unknown/malformed/proxy/accessor payloads, owner/
registry/census failures and event4097 remain fatal. All original actions, target
and context32-ID caps, tombstones and complete census checks continue after summary
saturation. Do not retain dropped payloads, raw strings/IDs or deferred callbacks.
Reserve independently exactly-once first-fault evidence even after row32; preserve
the original failure if observation itself fails. Acceptance never depends on a
truncated summary. Test valid and malformed row33, competing faults, event4097,
maximum serialized bytes and accounting equality. This explicitly supersedes
166's fatal-on-valid-summary-storage-exhaustion rule only in the new diagnostic.

## Producer and resource contract

Stage the established six-file extension layout: new DEV-only adapter, worker
and manifest, plus unchanged production reader, URL policy and native-rights
module. Adapter and manifest explicitly identify four invented cases and fixture
permissions, never the old32-case study or future168-case producer identity.
The actual entrypoint of any closed experiment remains unused and immutable.
Pure reviewed code may be imported or explicitly adapted under a new source
ledger; every consequential adaptation is included in source review.

The reviewed composition is209 source entries: original187, the established ten
helper/freeze entries, ten new owned files, this decision and the one immutable
pure-code dependency
`exact-browser-infrastructure-v1/compatibility-variant.mjs`. Authenticate that
dependency SHA2562d0309b15a7a74fe7a440c041a3c7592c7369b67258cb2f46db4c2723e71c07d
before dynamic import. Reuse its infrastructure policy, not its actual entrypoint,
old output/freeze or unchanged article-incompatible registry. All transitive
executed source remains within the authenticated inventory.

Native ordinals are exactly1–4 for this diagnostic. Preserve read-to-attestation,
same-document policy snapshots and bounded captured text. Start each absolute20s
article lease BEFORE its first setup RPC, not after ten setup calls. Each dispatch
rechecks the remaining lease. Setup, Page authentication, foreground observation,
rights, read and attestation all consume that same lease. Retirement time cannot
authorize another read, input publication or late success. No timeout releases capacity before the actual
operation settles; unresolved work is fatal and retained for owned cleanup.
RPC maximum remains10s, context/browser close2s each. Bound retirement separately:
page-close plus callback drain10s, optional target census10s and detach10s.

Set prospective active diagnostic ceiling360s with separate60s cleanup/failure
reserve, before source freeze. There is no DNS/origin-policy network phase.
The budget covers startup45s, four cases at20+30s, final checks20s, closes4s and
guardian ACK15s, with76s bounded overhead reserve. Node's absolute bound is350s;
the guardian enforces360s active/420s including cleanup. Add a NEW60s cumulative
owned-Job user+kernel CPU ceiling, including exited children:166 had no CPU ceiling.
Verify actual Job accounting and its embedded Python AST negative tests. Other
RAM/heap/owned-Job/disk/log/logical registry bounds and strict frozen system paths
remain those accepted by the current baseline; enumerate their exact values and
worst-case serialized report bound in the implementation before acceptance.
No source/output rewrites, retry, provider call or public request after failure.

## Source and execution gates

After design acceptance, Matcher owns new files under
`spikes/topic-resolution/harness/experimental/native-article-reader-dev-v1/`:
run.mjs, supervise.py, source-ledger.js, article-owner.mjs, native-adapter.js,

and the later compact evidence receipt. Additional files require explicit review,
not a silent source-closure change.

First inspect and test the finite owner state machine, fixture policy and source
composition using invented clients only. Include callbacks before Page promise
resolution, wrong context/target/loader, duplicate targets, retired callbacks,
unsupported rights, head mutation, bad document ID, timeout without settlement,
census omissions/extras, maximum output and cleanup failure. Root and independent
Trust must read the complete source and verify all changed producer paths.

Preparation, exact actual source-freeze audit and ONE native DEV invocation are
separate gates, each requiring root and Trust acceptance of the preceding result.
The Python guardian's embedded code must be executed independently in its actual
parsed form as well as covered by JS tests. Keep closed old source/output
immutable and do not mistake an exported helper test for actual guardian proof.
The actual run is closed whether it passes or fails; no automatic second attempt.

Only after this native diagnostic passes may a separately reviewed acquisition
protocol be proposed for the168-case panel. That protocol must keep each public
document's rights checks, paired body/title E5 and fitting phases honest. It may
use four-case fresh profiles with batch-local ordinals, but no TEST acquisition
before selected CAL policy is persisted and independently audited. The diagnostic
does not authorize that later collection or model/artifact access.
