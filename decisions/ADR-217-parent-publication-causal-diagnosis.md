## Source facts and limits of attribution

The actual v20 IO publishExclusive sequence creates and verifies a pending file,
obtains its native before proof, creates the final hardlink, obtains the native
after proof and performs a final proof-backed read before its original publication
Promise settles. File visibility alone does not prove these originals settled.

The actual parent finish method stops its initial pump loop when the final
finish.request.json exists. It checks the checkpoint and reads the result/freeze,
then rechecks sources, before its later pending-proof drain loop. A long read or
recheck can therefore delay remaining publication exchanges. Existing15-second
exchange/finish deadlines and the original phase deadline must not be reset,
relaxed or replaced.

The parent's frame_until is set and cleared inside pump, after physical write
and commit. Stopping pumping at file visibility does NOT by itself leave that
parent frame timer active. A later pump or the child's independent exchange
deadline may fail, but that is not a saved runtime observation.

The actual native sampler catches exceptions in its protected try and substitutes
proof-failed after closing all retained handles. That can mask an inner guard
predicate; both proof-failed and proof-frame-deadline are absent from the existing
finite supervisor projection. Adding those names alone would not recover the
inner site or prove the actual cause. This decision does not alter that behavior.

Native's authenticated pure evaluation of saved read_result/decode_freeze and
finish bindings passes with invented native/checkpoint capabilities. A retained
checkpoint history invented for a test is not a replay of actual history. The
saved1466 result and1474 finish heads do not prove later publication settlement.

## Required causal cases

The first case must run actual IO publication until the final hardlink is visible
while its after-proof or final-read original is still pending. Assert that the
actual publication Promise, pending originals and operation ownership are not
settled at visibility. Resolve the SAME originals later; never substitute a
racing observer, fulfilled proxy or logical cancellation.

Drive actual parent finish through that visible-file schedule. Make its result/
source recheck advance the fake clock across the original child's exchange
deadline before remaining frames are serviced. Preserve the exact generated
failure and every original physical write/cleanup obligation. This is an
invented source-supported counterexample, not the actual ADR216 cause.

The paired Python case records the actual unchanged-parent outcome, including
an ACK if its own predicates permit one. It must not synthesize a child exit
merely to force parent failure. The child's exact late-continuation failure is
established separately by the actual Node wire under the shared invented
schedule; these remain independent source executions, not physical IPC or
actual-cause proof. Injected unexpected-exit coverage is a separate adversary.

Use a contrast schedule that services those SAME real publication exchanges
before the expensive validation schedule under the SAME deadlines. Do not patch
the parent or label the contrast an accepted fix. It may show only that the
input interleaving matters. ACK is forbidden before required original write,
flush and service commit, result/source checks and existing quiescence proofs.
A later design must establish a privately derived, complete publication proof;
mere queue emptiness, fixed sequence offsets, caller flags, file visibility,
snapshot pause or guessed elapsed time can never provide that proof.

Include all of these adversaries:

- A final-read frame arrives after an empty-queue snapshot.
- A prepared reply exists but its original write/flush remains pending.
- A write rejects or never settles, including after final file visibility.
- Clock expiry before and after physical response settlement; no lease renewal.
- Source/result drift, malformed/mismatched/evicted checkpoints and wrong phase/binding.
- EOF, extra frames, unexpected process exit and mandatory cleanup.
- First failure followed by cleanup failure without replacement of the first.
- Guard failure inside the actual native sampler followed by its existing proof-failed masking and complete close order.

The last case is diagnostic evidence of masking only. Do not add an observation
latch, widen the runtime code projection, preserve a new raw exception reference,
change cleanup ordering or alter which original exception the actual sampler
throws in this harness.
