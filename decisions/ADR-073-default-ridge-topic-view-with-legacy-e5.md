# ADR-073: Owner-local Ridge1 default with reversible Legacy E5

Status: owner approved; implemented, independently reviewed and locally activated.
Date: 2026-10-10.

## Explicit owner decision

After reviewing ADR-072's fresh results, the owner requests Ridge1 as the
standard after restart, a Legacy E5 rollback, and old/new assignments in Topic
Atlas. This explicitly accepts the observed trade-off: fresh news298 gives
406 correct/7 wrong grouped pairs versus the diagonal control's 84/3; the
independent five-language challenge gives 88/4 versus 73/21. The frozen
per-cohort screen remains failed. This separate product decision does not
rewrite that evidence as passed, calibrated identity or store/legal clearance.

The standing owner-local fitted-weight approval covers reconstructing the
exact 475-report fit and installing coefficients only in ignored service data.
No new fresh evaluation, tuning, provider inference, download, remote service,
corpus/model publication or rights conclusion follows.

## Scope of the standard

The extension's standard **Topic matching** uses the existing authenticated,
revision-bound, Source-scoped alternate discussion read. Ridge1 transforms
the already saved 384D E5 vectors transiently on this PC. No page revisit,
larger browser model, second saved vector, new capture permission or page-text
upload is introduced. The fixed policy is
`ridge1-qualified-complete-link/v1`, representation
`owner-local-linear-teacher-transfer/ridge1-v1`, floor 0.8639003810829322.
Qualification precedes indexing; unknown contexts remain eligible. Full-cross
checks, duplicate-independent evidence and fixed work/time/memory guards
remain. Capacity failure returns no partial partition.

The exact pure proposal is copied to production, not retuned against the
spent fresh sets. The legacy internal indexed BODY admission name is only an
implementation seam; the outer policy and representation truthfully identify
Ridge1. Normal loading requires the exact original parameter digest
`593a52ba9a5495a49ef00f4dae38770684389632f961b60ec07067fd8784b3e4`.
The bounded installed file is `apps/local-service/data/ridge1-topic-adapter-v1.json`.
Missing/corrupt/wrong weights disable the learned view; they cannot silently
activate old diagonal/BODY weights under the new name. Older service responses
are contract-compatible but cannot activate the standard Ridge1 UI.

This remains a reversible **read/presentation** policy. Canonical SQLite Topic
links, Source-root lineage, post IDs, replies, manual/legacy pins, origin links,
post writes and private Insight authority stay intact. Foreign canonical roots
remain read-only until their source is opened. This approval does not invent
historical lineage, migrate canonical conversations or expand cross-Topic
reply/AI-follow-up authority. Those architectural steps need separate review.

## Restart and comparison behavior

- Topic matching is the initial mode. An explicit **Legacy E5** choice is saved
  only in `chrome.storage.session`: popup closure and MV3 worker suspension do
  not undo it; Chrome restart or extension reload clears it. The old persistent
  mode preference is ignored. Reopening a popup is not a new browser session.
- Legacy E5 means the existing canonical E5 assignments, not the intermediate
  diagonal adapter. The extension can fall back truthfully to these discussions
  if Ridge1 is unavailable, without discarding unsent text or using stale data.
- Topic Atlas compares the same complete snapshot: **Topic-Matching** displays
  Ridge1's groups; **Legacy E5** displays canonical assignments. Selection stays
  anchored to a Source across switching and refresh. A valid learned preview
  is the document's initial mode; an explicit choice survives refresh.
- Map coordinates and nearest-vector scores still describe original E5/PCA;
  colors/membership change with the selected assignment. Do not imply this is
  a projection of the learned geometry. The separate rendering guard remains.

## Installation and verification

The reviewed one-shot installer reads only pinned local fit inputs/assets,
reconstructs original coefficients and requires the exact coefficient hash
before exclusive creation. It saves no article text, target/student vectors,
IDs or credentials. Bounded FD-safe reads, ignored-path checks and post-write
verification protect the fixed target; an existing file is never overwritten.
The frozen teacher helper still opens two configuration files by pathname
between receipt checks. Concurrent malicious local TEMP mutation can cause
failure/resource use, but exact final coefficient verification prevents
different weights from installation. This narrow limitation is documented,
not a claim of protection against a compromised local account.

Independent Trust review and six adversarial service checks passed before
installation. Generic synthetic artifacts are accepted only through trusted
composition for portable tests; the normal installed loader enforces the
original coefficient pin. Actual Chrome verification must use fabricated
coefficients/public synthetic pages in a disposable profile, no provider call.
The owner service may be briefly restarted for normal activation and isolated
QA; pairing, OAuth storage and SQLite are not reset. Final status records
installation, complete tests and actual-Chrome evidence before claiming done.

Release, source rights, provider spending/egress, private-page expansion,
hosting/deployment and app/store gates remain separate and unapproved.
