## Startup protocol and filesystem proofs

Use new exact startup-infrastructure-diagnostic/v1 DTOs with monotonic sequence,
request/response chain and original source/list/Node identities. READY asserts
fresh bootstrap identity, not completed child authentication. Parent samples
and seals the exact Node/optional original-console baseline once, then issues
STARTUP_ACK bound to READY and baseline. Child completes full source/package
authentication before importing the diagnostic policy or Playwright.

PROFILE_BEGIN binds the next fixed index and previous drain ACK. Parent validates
order, source identities, exact original baseline and reserves before ACK.
PROFILE_DRAIN binds index, result hash, physical summary and proof checkpoint.
It is accepted only after both context/browser close attempts and settlement of
all original operations/callback work. Parent independently proves return to
the exact sealed baseline using complete enumeration then held-handle census,
rechecks files/resources, and physically writes/publishes its ACK before another
profile begins. Between profiles the original Node remains alive; do not claim
the Job is empty. A failed profile's drain is terminal, never permission to retry.

Keep policy/listeners live through the drain ACK and recheck the first-fault
latch after it and immediately before the next PROFILE_BEGIN. A late callback
records terminal failure, not a rewritten earlier profile result or a new launch.
Define separate exact FAILED_PROFILE_DRAIN and FAILED_COMPLETE schemas: they may
attest clean failure retirement, never a healthy profile or startup success.
No success or failure drain ACK is issued while original work remains unsettled.

COMPLETE binds ordered profile results, drain ACKs, first fault and proof head.
Parent validates the stored result before authorizing Node exit, then separately
proves normal original Node exit, terminal pipes/settled threads, empty Job,
closed handles and final source/resource checks. Emergency termination makes
the diagnostic unsuccessful even if cleanup subsequently empties the Job.

Native opened-file/ancestor sampling accepts only authenticated CODE/package
keys and fixed diagnostic controls/output aliases. Before/after tickets bind
the original object identities; publication uses exact final/pending hardlink
pairs. Response/proof state advances only after the original write/flush settles.
No arbitrary caller leaf, artifact, model, metadata cohort or broad workspace
key. Sampling is explicitly non-atomic, not a kernel path sandbox. Failed work
stays sticky; bounded cleanup/publication may ignore work poison only for its
own fixed paths and absolute cleanup deadline, never for new normal work.
New publish_pair takes explicit exact allowlisted paths/caps/native capabilities;
never call the old v13 publish function with its captured workspace. Terminal
proof/report/cleanup controls have their own closed allowlists and absolute
deadline fences; they cannot reset a poisoned normal guard or grant work.
