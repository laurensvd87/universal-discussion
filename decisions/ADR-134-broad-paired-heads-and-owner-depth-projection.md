## New paired supervised candidate

Adapt the proven bounded affine Ridge head algorithm into separately versioned
modules accepting ONLY the explicit weighted-body/title representation. Preserve
closed ADR-131/132 artifacts and source bytes. Model/policy hashes include the
paired namespace and exact adapter definition; title-only use is not silently
treated as calibrated body input. Nodes receive ancestor-inclusive labels and
unrelated child heads receive negatives. Generic parents, unknown children,
insufficient captures and misleading titles need explicit fresh paired evidence.

The proposed large1038-row corpus was judged likely to encourage padding by its
independent author. Use a transparently reduced fully authored457-row feasibility
screen instead:130training/67development/193calibration/67lockedtest,63nodes, EN/DE/
FR/ES/NL. No generated template copies or translated families across splits.
This is NOT enough independent web evidence for production confidence claims.

Before encoding, freeze source/corpus/taxonomy/protocol/model-input hashes.
Compare weights .75/.5/.25 and lambdas .01/.1/1 on development only, bounded nine
fits and128million aggregate counted training arithmetic units. Separately
calibrate the selected model using >=3accepted groups and empirical precision1;
those tiny calibration supports are not statistical guarantees. Preserve the
selected model/policy before one locked test. Retain the existing support,
uncertainty and representative-web release gates; never relabel a failed gate.

## Implemented owner grouping projection

`experimental-hierarchy-page-candidate.js` compiles adapter/model/policy once and
returns the supported path plus its owner-selected display cut. Default maximum
depth is owner-wide; a rule for a specific topic can override it. The deepest
matching rule on the FULL supported path wins. A cut only shortens an accepted
path: it cannot invent a child, cross branches or override insufficient confidence.
This supports general niche groups while allowing popular branches to become
more specific without changing classifier certainty or moving old discussions.

Owner configuration has a revision and hash. The pure component supplies no
owner appointment, account inference, dashboard admin route or persistence.
Every output explicitly denies assignment/write/AI authority. Canonical Source
proof, actor and discussion destination are separate and unchanged.
