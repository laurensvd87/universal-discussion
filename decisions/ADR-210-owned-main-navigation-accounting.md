and the fourth start. Root and independent saved audits authenticate18 control
pairs,11,595 JSON bytes,587 bytes of stderr and all243 unchanged input endpins.
The precise owner refusal is repeat while navigating; the failed event's URL

cohort, E5 encoding, fit, result, selection or TEST completed. Evidence FILE:
e04c505fa3109c91f4fbbd922fb394cf559042a099309f203af3752cc3516f56.

Installed, pinned Playwright routes new-document and same-document navigation
through its public framenavigated event and exposes only the Frame there. The
owned capture independently receives typed CDP Page.frameNavigated, but does not
currently subscribe to Page.navigatedWithinDocument. Consequently, rejecting

fact does NOT prove what caused the actual repeat or identify its URL.

The correction must preserve exact fresh-document, network, native-document and
rights checks. It may account exact-URL same-document activity without treating
it as another document, a new navigation fact or permission to read.

## Typed same-document observation

sameDocument requires the original session/page/token and exactly three
enumerable own data fields: frameId, url, navigationType. Reject proxies before
reflection and all unsafe/missing/extra descriptors without invoking hooks.
Require the exact owned main frame and a privately successful fresh commit in
this same component. A same-document event before that commit is fatal.

fresh commit remains the sole document-commit association. Existing independent
reply/commit/loader/TLS/public-peer/header and native document-ID checks remain.

## Balance and lifecycle

Maintain only bounded counters: expected public notifications equal the number
of successful fresh commits (zero or one) plus accepted same-document events.
Either public or typed notifications may arrive first. Prefix imbalance is
pending, never authority. Count consistency is NOT event-by-event causal pairing:
indistinguishable public callbacks can mathematically compensate for omitted
counterparts. The maintained event-source bindings and independent typed document
and native checks remain essential. Do not claim to reconstruct missing events.

The future existing readiness loop must wait for both the original seven facts
and this balance under the ORIGINAL20-second lease, using its existing wait.
Callbacks may settle pending counts; native operations may not run while they
are unmatched. Every native read, rights, frame, final and pre-close fence must
assert balance before and after awaited work, plus original journey completion
and owner reading state where reads are involved. No deadline, timer or lease
renewal is added. Unmatched debt at a post-await/read/final fence fails sticky;
ONLY the initial existing readiness loop waits. There is no implicit helper
recovery or additional wait barrier. The standalone status is not a substitute
for these checks.

Lifecycle is active, sealed, retiring, released, with sticky failure throughout.
assertBalanced requires one fresh commit, balanced notifications, original
journey.assertComplete(token) and owner.assertReading. seal requires these same
checks immediately before collected-row publication. After sealing, ANY fresh,
same-document or public main-navigation observation fails the WHOLE phase:
never wait for a compensating event or rewrite an already fenced row.

retire requires ZERO unmatched debt, but must also permit fresh=0/public=0 for
normal unavailable/aborted transport. That does not invent a complete journey,
reading state or collected row. Preserve existing transport abort, actual read
revocation, owner retirement, close, target destruction, census and all physical
callback/denial/socket/coordinator drains. Close and destruction never settle
accounting debt. Existing terminal main-navigation refusal remains unchanged.

release is idempotent and callable despite sticky failure or an expired deadline.
It invokes no guard, clock or operator. It revokes only this component and clears its captured capabilities,
operators, strings and first-error association before any later callback. It
MUST NOT call owner.release, journey.retire or delegated cleanup: the actual
owner is shared across four articles and has its own normal release boundary.

aggregate article/batch callback limits. Check overflow BEFORE increment. No
event queue, raw payload/history, timestamp or URL diagnostic is retained.
