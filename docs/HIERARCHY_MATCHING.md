## Automatic topic creation remains the next implementation step

The installed named taxonomy is explicit. Browsing/crawling populates Sources
and their assignments; it does not currently invent a new named topic or event.
The owner clarified that visits must also supply new, potentially very specific
topics, including news events that did not exist before. Named topics must tell
people what they are commenting on. This requirement keeps the overall goal open.

Build background discovery separately from fast read/write routing and the fixed
broad classifier. Compare bounded incremental groups and parent-scoped batch
discovery using real same-event/different-event cases. A new group is a proposal,
not proof of taxonomy ancestry or a safe merge. Distinguish durable subjects from
dated events and distinguish a new development from another story about the same
entity. Use available public titles for provisional labels without an obligatory
LLM call. Do not transmit browsing text to a provider by default.

Give approved/generated topics stable IDs independent of classifier releases.
Preserve original post destinations and explicit author context through later
renames, merges, splits and parent cuts. Include singletons and duplicates in the
evaluation, avoid a new globally visible topic per visit, and retain a clear
page-only commenting route while discovery runs. The current immutable matcher
registration cannot be rebuilt globally for every new story; a separate dynamic
registry and transactional membership boundary need an explicit design.

HDBSCAN's prediction API assigns to its original clusters; finding new clusters
requires new fitting. [Its API documentation](https://hdbscan.readthedocs.io/en/latest/api.html#hdbscan.prediction.approximate_predict)
explains that distinction. [BERTopic's online documentation](https://maartengr.github.io/BERTopic/getting_started/online/online.html)
describes incremental/merge approaches and DBSTREAM as an option for new clusters.
These are candidates to compare, not newly accepted production dependencies.
The earlier frozen nonvisual UMAP/HDBSCAN study failed its grouping checks and
remains rejected; it is not retroactively new-event evidence.
