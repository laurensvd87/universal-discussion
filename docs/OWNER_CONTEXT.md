# Owner Intent / Constraints

- Goal is to give a capable coding LLM enough context to autonomously organize the work, not merely generate code.
- The active coding agent should first create an appropriate, lean agent structure for development and adjacent work such as marketing, hosting, security and rollout.
- The owner wants existing AI subscriptions to enable useful contributions even
  without API keys, through supported mechanisms and explicit publication.
- Semantic clustering is considered crucial to adoption because URL-by-URL discussions fragment network effects.
- Early adopters should receive immediate utility from their own AI even when no human content exists.
- Useful AI outputs may become persistent public contributions only through explicit/publication permission and must remain visibly AI-authored.
- Eventual reach should include major browsers, Android and iOS. Specific UI integration (extension/sidebar/bubble/share sheet/etc.) is deliberately deferred.
- Initial infrastructure should be inexpensive. Do not assume proprietary datacenters or GPUs are required.
- Product quality/trust matters more than manufacturing apparent activity.
- Browser extension is first; Android/iOS follow. Reuse domain/network contracts,
  with sharing/Safari/WebView adapters chosen from platform evidence.
- The 2026-09-27 instruction requests a critical reassessment and autonomous
  routine engineering, not another step-by-step owner questionnaire (ADR-014).
- Ask explicitly before actual expanded page-data/privacy/security/provider,
  spending, deployment or publication boundaries. Bundle related decisions in a
  concrete proposal; do not ask again for unchanged approved local work.
- Synthetic owner review is finished (6/6). Stop and ask before the later
  200–250-pair provenance-approved task; independent-human work is needed then,
  not for each local implementation increment.
