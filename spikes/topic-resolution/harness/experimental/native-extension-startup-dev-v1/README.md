# Native extension startup DEV diagnostic

Source-only ADR151 prerequisite. Default execution is inert. No browser launch,
staging, source freeze or diagnostic run is authorized by these files alone.

The fixed sequential variants use fresh package-owned persistent contexts with
service workers `block`, then `allow`. They retain only the initial blank anchor.
All host resolution is denied, HTTP/HTTPS requests are aborted and WebSockets
closed before extension load. This is not OS-wide egress isolation.

Only the six original repository CODE files are staged in this namespace after
checking the immutable ADR150 source freeze. No old output, body, packet, model,
asset, account, app, provider or database is read. A real owned worker may expose
API presence and actual window metadata and perform `beginStudy`/`endStudy` with
the fixed metadata, never a content observation, skip or rights read.

Controlled operation traces retain names, outcomes and finite native-error
classes, never raw errors, URLs, targets, function source or content. A settled
API incompatibility ends that variant. Unknown callbacks, programming errors,
source changes, unresolved physical operations and cleanup failures end the
whole diagnostic. A settled eight-second worker wait means only
`not-observed-within-8s`, not proof that a worker never exists.

The second context requires physical callback/operation drain and a separate
guardian same-Job Node-only ACK. Each context has two lifetime reserved closes;
fresh capacity follows only confirmed drain. Job, host, profile, output and time
limits remain external guardian responsibilities, not a claim that Playwright's
internal transport has the same raw-message/pending caps as the coordinator.

After review, `--prepare` creates new exclusive metadata only; `--run-dev` requires
the exact guardian handshake. Neither command is permission to execute. All
failed output is retained; no retry, fallback, rescue or semantic-quality claim.
