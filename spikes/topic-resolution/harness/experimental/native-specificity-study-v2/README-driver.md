# Supervised study execution

ADR180's successor driver retains the fixed168-case collector, paired E5 encoder
and hierarchical classifier. Its finite failure diagnostics address the lost
exception context in ADR179's failed first TRAIN/CAL attempt. Every original v1
file remains unchanged; no failed input is reused. Execution remains disabled
until complete successor source review and separate phase decisions.

The native parent authenticates the CODE and maintained Playwright package before
starting Node and assigning its owned Job. One default-inert pipe adapter may
load before reading the original assignment header. Only after that header may
the driver import the filesystem adapter and fixed catalog. READY binds original
Node identity and a fresh workspace; the baseline ACK precedes the child's full
CODE/package/metadata/artifact checks. No environment flag grants execution.

Preparation creates only its own fresh `output/prepare-r3/node-owned` directory and
publishes the fixed freeze there. TRAIN/CAL and TEST use separate fresh outputs;
they cannot adopt old profiles or outputs. The base ledger catalog remains
independent of the phase-specific IO control catalog. TEST additionally requires
the separately pinned independent audit and exact three TRAIN files before its
first URL. TEST is never automatically started after calibration. The fixed phase
mapping uses only the new v2 namespace. Original v1 outputs and source maps remain
untouched and count against the same aggregate resource caps. Callers cannot
supply an output leaf or request adoption of old files.

A diagnostic-only boundary preserves the exact original thrown value, including
falsy values. It emits at most one900-byte JSON line plus the unchanged31-byte
generic refusal. Driver stage names are fixed literals. Capture details come
only from the authenticated collector's private first-fault reader and finite DTO
validator. The boundary never reads exception messages, names, stacks or causes.
Projection or emission failure omits diagnostics without replacing the original
failure. Stage/RPC labels identify observation locations, not causal proof. The
actual synchronous emitter is the original parent's existing stderr file; no
new path, provider request, retry or success/availability path is introduced.

Each batch receives its actual start ACK before setup/DNS/capture. Staging uses
the exact seven reviewed files. Policy requests reuse the already validated DNS
selection, with ordinary HTTPS and peer checks still enforced. The parent alone
counts browser profile files, including filenames with spaces; Node's ASCII-only
workspace walker is not used for profiles. Batch teardown and the actual drain
ACK precede raw-row release and the next batch.

TRAIN/TEST authenticate the nine actual asset files only after final cohort
drain, before encoder initialization, then recheck them and every source after
encoding and before publication. Preparation checks those bytes in its separate
allowed phase. Model/phase deadlines remain fixed and are independently enforced
by the native parent.

Results, finish request and completion bind healthy idle pre-publication proof
checkpoints, not a falsely claimed terminal chain. The finish ACK is obtained
while Node is alive. Only after completion publication and settled channel state
may Node allow natural exit. Success still requires the parent's normal exit,
settled pipes, final byte checks and empty owned Job. Fatal Node failure exits
abnormally; parent-owned cleanup remains mandatory and cannot become success.

Focused tests cover helpers, fake channels/metadata and source ordering. Actual
native preparation, public collection, model calls and quality gates remain
separate executed-evidence requirements.
