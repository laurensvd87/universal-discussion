# Current-producer controls v1

Code-only, inert by default. This is ADR143's compatibility prerequisite, not
the proposed final32 collector, a classifier test or an activation. The four
fixed consumed TRAIN articles are Tetris EN, Schach DE, Go (bordspel) NL and
Octopoda FR. No final metadata, vectors, model, DB, app, credentials or owner
browser state is read. Earlier probes and ADR142 files remain untouched.

## Prospective phases

`node run.mjs` and `python supervise.py` report no action. After independent
review and a separately created source freeze, explicit supervised modes are
`--static-controls` and `--browser-controls`. These commands are documentation,
not permission to run. Each owns a fresh exclusive D: directory, respectively
`output-static` and `output-browser`, with persistent markers, logs and results.
An existing directory prevents replay. Nothing is deleted or retried.

The root-owned `freeze.json` must have exact fields `schema`, `sourceHashes`,
`protocolSha256`, `controlsHash`, `freezeHash`, with schema
`current-producer-controls-freeze/v1`. Hash the ordered object without
`freezeHash` using SHA256 of UTF8 JSON.stringify; `controlsHash` similarly hashes
the exported fixed `CONTROLS`. `sourceHashes` contains the thirteen exported
`SOURCE_FILES` in their declared order. Freeze after all seven new files pass
review. No freeze/receipt/result is generated by pure tests or default entry.
Both runner and supervisor refuse missing/drifted freeze; the frozen source map
and actual freeze-byte hash link all evidence. JSON is parsed from its initially
hashed buffer. Initial source buffers and pinned dependencies are fresh-read at
the end; browser also rechecks prior static result and supervisor receipt bytes.
This detects ordinary source drift, not hostile loaded-module attestation.

Static controls use unchanged `createPublicFetcher`, robots/TDM parsers and
`captureStaticHtml`. No metadata pruning, Wikipedia lead extraction or fallback
builder is imported. There are at most eight policy and four page requests,
15 seconds per request, 240 seconds policy phase and a 360-second owned Job.
Static bodies are used transiently for the exact live extractor and then only
metadata is persisted. The original response buffer is wiped. The extractor's
own behaviour, including its existing preferred/fallback choice, is unchanged;
this harness never adds another extractor fallback.

Rights/transport eligibility is separate from extraction availability. Headers
and the static parser's DOM directives must be checked. A parsing exception
means unknown page policy and grants no browser eligibility. Completed clean
policy checks followed by insufficient extracted text can be browser-eligible.
Robots/TDM denial or malformed/unknown rights never grants page capture. Only the
unchanged old NL adapter's exact raw hash, decoded hash, origin and full DENY
line may receive the known percent-space repair. No new repair declaration is
accepted. Typed ordinary policy/HTTP/time/capacity reasons are fixed in
`protocol.json`; unexpected transport failures, aborts and global deadlines are
fatal rather than usable-input refusals. No attempt is silently retried.

Browser controls require the exact prior static result and its successful
own-Job supervisor receipt, unchanged source map and freeze, and at least two
rights/transport-eligible controls. All four denominators remain explicit.
Fresh robots/TDM checks are performed again for every fixed origin in this batch,
not reused from static results. At most eight requests, each <=5 seconds, plus
all pacing must fit the complete 60-second policy phase. Required spacing is
at least two seconds and never shortens a crawl delay. A delay that cannot fit
marks that origin unavailable; known refusal is held only within this batch.

## Browser document evidence

The reviewed V2 CDP pipe and isolation are mechanically reused in a new namespace.
Chrome runs only from either fixed Program Files installation, headless/hidden,
in a fresh retained D: profile. Node must receive the exact stdin handshake
AFTER assignment to the own Win32 Job, before Chrome spawn or fetch work.
No existing-browser attachment, debug TCP port, extension, pairing, account,
certificate bypass, sandbox disable, login or consent automation exists.

Auto-attach pauses targets before creation. Non-main pages/workers are closed;
main-target setup preserves cache disabling, service-worker bypass,
ServiceWorker.enable then stopAllWorkers, download/permission/dialog refusal,
WebSocket blocking and Fetch interception before renderer resume. Browser flags
retain background-networking/component-update/domain-reliability/sync/phishing
update/default-app and autoplay restrictions. Cookies/Authorization headers are
removed at Request interception; a fresh anonymous page may nevertheless set
cookies inside this isolated profile. No cookie/profile read API is used.

Only GET/HEAD on the four literal language Wikipedia hosts and explicit resource
types is allowed; Document requests must equal the current fixed control URL.
No additional script host is allowed. Images, media, fonts, workers, WebSockets,
account paths, encoded aliases, known telemetry and all other hosts are blocked.
Blocked resources may make extraction unavailable; there is no allowlist rescue.

The browser intercepts its OWN main-document Response as well as Request. It
checks exact final URL, successful status and bounded X-Robots/TDM headers before
continuation. The later Network response must agree on request ID, main frame,
navigation loader, URL/status, HTML MIME, ordinary TLS security and an observed
global-public remote address. Any observed private address is fatal. This is
POST-CONNECT evidence: public-fetch DNS pinning does not pin Chrome DNS, nor do
CDP interception and flags prove complete Chrome/OS egress isolation. Fixed
reviewed trusted public hosts and ordinary certificate validation are the scope.

One observation occurs at the matching main-frame loader's DOMContentLoaded +2s
inside an absolute20s navigation/observation lease. DCL after18s does not extend
the lease. Initial about:blank/stale/subframe events cannot satisfy it. The
isolated world is prepared before the scheduled observation when possible;
there is no later body recapture. Exact frame/loader/URL are checked before and
after evaluation and unexpected main-document changes invalidate the observation.
Header approval is necessary, not sufficient: bounded DOM directives are checked
at the snapshot too, then the exact hash-pinned current browser reader runs.
The reader's own missing-region/budget/unsupported status remains explicit.
Valid noisy/generic output remains collected; no semantic content filter exists.

Document ID in output is a harness-generated incarnation hash, NOT the native
extension document ID or a posting/provider attestation. Persisted captures
contain only extractor, title/body SHA, lengths and <=160 UTF16 prefixes. No
full body/HTML, raw response headers, IP addresses, cookies, vectors or arbitrary
error strings are retained. Reviewed fixed CDP stage/method and integer error
code remain observable on command failure, never server text/parameters/stacks.

## Resource envelope and honest limits

The copied standard-library supervisor owns Node and every Chrome descendant in
one unnamed Win32 Job, kill-on-close, no breakaway,1536MiB Job committed-memory
limit. Every50ms it checks at most128 Job PIDs, confirming each opened handle's
membership before memory reads, summed RSS/private<=1536MiB, available physical
and commit>=1GiB, C:free>=768MiB and D:free>=512MiB. RSS can double-count shared
pages and is intentionally conservative. Unverifiable PID exit races fail closed.
Only the exact own Node/Job can be killed, never process names or broad searches.
Fresh TEMP/TMP is under the phase's D: output; inherited credentials and
NODE_OPTIONS are excluded. Node heap is256MiB; one worker-thread environment.

Browser child-active cutoff is170s (Node guard165s), followed by at most5s own
Job drain and remaining final source/receipt checks inside180s observed total.
Its policy phase<=60s, four observation leases<=80s, Node startup/overhead/close/
source checks<=35s and final own-tree drain<=5s compose the declared180s ceiling.
Static cutoff is350s (Node345s) with drain/final checks inside360s total. Actual
unverifiable/exceeded wall or cleanup is failure, not assumed compliance.
After TerminateJobObject the supervisor polls for zero Job members and confirms
own Node exit before success. Cleanup failure still leaves a failure receipt.
Logs+result<=256KiB; result<=192KiB. Profile/cache disk growth is not covered by
that metadata cap; drive reserves remain checked and profile evidence is retained.

Static compatibility requires >=2 rights/transport-eligible rows. Browser proof
requires >=2 collected rows with full response/loader/directive witnesses. These
are compatibility prerequisites, not semantic accuracy or permission to collect
final inputs. Both results account for all four controls. A completed phase can
have compatibilityPrerequisitePassed:false; root must stop rather than retry.
Root and independent review of actual proof precede any later final32 freeze.
