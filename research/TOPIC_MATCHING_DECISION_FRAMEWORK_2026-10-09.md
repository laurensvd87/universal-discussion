# Precision-first same-story Topic decision framework

Status: offline design hypothesis, 2026-10-09. No matcher, representation, retention, model, migration, or release decision. The live service remains the ADR-023 provisional policy: one body-derived 384D E5 vector per Source, a 0.90 floor, 0.94 tight support, a 0.04 competing-source margin, and synchronous full eligible-catalog replanning under a 10-second work budget ([planner](../apps/local-service/src/domain/adaptive-topics.js)). That is not a path to one million Sources: the outside-source check and pair/group scans grow with the catalog.

## What the evidence establishes

- Broad embedding retrieval is much stronger than safe admission. A same-event report was in the first three candidates for 245/254 eligible Wikinews test queries, while fixed 0.94 grouping joined 9/534 true pairs ([Wikinews baseline](../apps/local-service/experiments/topic-encoder/wikinews-benchmark-v1/RESULTS.md)). Wikinews links language editions, not independent publisher viewpoints.
- On GlobeSumm, a frozen nearest-veto graph joined 256/1,710 same-event test pairs with no test false joins, but made **25 false train joins in five mixed groups** and recovered **zero complete events** on every split ([GlobeSumm graph](../apps/local-service/experiments/topic-encoder/globesumm-graph-v1/RESULTS.md)). Its global nearest-neighbor veto also violates [ADR-064](../decisions/ADR-064-event-evidence-topic-graph.md)'s scale requirement. GlobeSumm lacks viewpoint and reliable adjacent-development family/publisher labels; its one-shot test is spent for this rule.
- A frozen synthetic five-language viewpoint holdout exposed eight same-family false joins from a looser triangle; the veto removed them on that set but had seven false joins on synthetic train ([v6 results](../apps/local-service/experiments/topic-encoder/adaptive-topic-graph-v1/RESULTS.md)). Synthetic success did not transfer safely. Title-only E5 then reduced true joins and retrieval on GlobeSumm train under all three frozen rules, so that line stopped before validation ([title-only result](../apps/local-service/experiments/topic-encoder/globesumm-title-v1/RESULTS.md)). These results reject simple cosine relaxation, global veto, and title-only substitution as current activation choices; they do not prove that a new event representation will work.

## Candidate architecture to test

1. **Two outputs, two standards of evidence.** Use the existing broad vector and indexed title/URL cues to retrieve *related* Sources and discussions. A related result never changes the primary Topic or root-post route. Assign a Source to a shared same-story Topic only when direct evidence identifies the same principal action or announcement and rules out plausible nearby developments. Otherwise give it a provisional primary Topic and show bounded, explicitly labeled related discussions. A page spanning several developments has one primary destination plus related destinations, not an implicit multi-Topic root route.
2. **Expandable local search.** At million-Source scale, combine an approximate vector index with Unicode-normalized title/URL postings; fetch successive batches, exact-rerank their candidates, and expand while the inspected boundary still holds plausible event evidence. Deduplicate same-URL/syndicated copies before counting support. The batch size is a retrieval unit, never a Topic-size cap. An index recall audit and an explicit work budget are required. If the budget or approximate search leaves competing hypotheses unresolved, defer the hard join; do not assert that unseen pages are safe. Search and group updates should touch an indexed affected neighborhood, not every Source. A large established Topic remains addressable through a versioned, expanding exemplar cover and membership postings rather than a fixed top-K or complete-link pass over all members.
3. **Event evidence before graph growth.** In the candidate neighborhood, test a multilingual event nucleus: actor, central action, object, distinctive qualifier/location/product variant, and explicit incompatible identifiers. Time is supporting evidence for news, not a universal cutoff for product issues. Opinion polarity and publisher wording must not define identity. Require independently sourced corroboration for a seed; copied headlines are one signal. Add a Source only if direct evidence supports the group's event hypothesis across relevant exemplars and no supported conflicting hypothesis remains. Refresh exemplars as language, framing, and detail regions emerge. Never allow a chain of individually plausible but collectively different developments to merge by transitivity. When a report says one policy *caused* a later outcome, retain two event Topics linked as related; a later update can be linked to its predecessor without silently merging their discussions. This event verifier and its multilingual reliability are **hypotheses**, not existing product capabilities.
4. **Stable discussion routing.** Store an explicit policy/representation version and evidence status with each provisional Source assignment. Candidate recomputation first produces a read-only diff: Sources moving, groups splitting/merging, existing roots affected, pins, and unresolved cases. A permitted migration then moves complete Source-anchored root subthreads transactionally; reply-origin links do not set grouping. Preserve manual pins and protected legacy roots, and never infer missing historical Source lineage. Make retry, insertion-order, deletion, restart, and rollback behavior deterministic. A proposed automatic merge that would reroute existing human discussion deserves stricter evidence than showing two groups as related. No such migration is authorized now ([ADR-064](../decisions/ADR-064-event-evidence-topic-graph.md), [ADR-067](../decisions/ADR-067-adaptive-topic-admission-research.md)).

## Representation choices

| Candidate | Current evidence | Decision boundary |
| --- | --- | --- |
| Retained body-E5 plus title/URL | Already available; useful candidate retrieval, weak precise-event admission. | First prototype should use this unchanged data, with no new capture or storage. |
| Ephemeral title+lead E5 | Helpful research view, including GlobeSumm retrieval; differs from live body-E5. | Retaining or transmitting it would change the approved input/representation and needs owner/Trust review. |
| Title-only E5 | Faster in one local train run, but worse retrieval and true joins; still false groups. | Do not advance this as a second stored vector. |
| Compact event-focused on-device encoder or adapter | Plausible way to separate same story from same theme; not validated. Prior small synthetic heads transferred poorly. | First prove rights-cleared multilingual/viewpoint performance offline, then assess model license, asset size, CPU, memory, power, and retained-data policy. No download or shipment implied. |

Any second retained vector, structured event signature, body-derived facts, changed upload, or replacement model needs a separate privacy/retention, rights, model-size, and migration gate. At one million Sources, even one float32 384D vector is about 1.5 GB before index and database overhead; adding another full vector is a material storage choice. Compression is a separate precision and rebuild experiment, not a free assumption.

## Offline acceptance sequence and stop/go gates

1. Pre-register the same-story boundary and disagreement protocol. Assemble rights-reviewed, independently adjudicated real cross-publisher pairs with opposing viewpoints, several languages, neighboring developments of the same entity, multi-event articles, updates/consequences, product variants, duplicates, and singleton stories. Split by event *and* related family/publisher template where possible. Keep a new test set sealed until method, thresholds, code, input hashes, and metrics are frozen; the scored v6 and GlobeSumm sets are development evidence, not fresh holdouts.
2. First verify retrieval recall and indexed boundary behavior at 1M+ synthetic/catalog Sources, including a 100+ report single event, insertions/deletions, duplicate floods, and budget exhaustion. Report recall lost to indexing separately from verifier abstentions, p50/p95/p99 ingest and query latency, memory/disk, rebuild time, and percentage unresolved. A fixed K or global scan fails this gate even if its small-set score is high.
3. Then score the *partition*: false joined pairs, mixed groups, affected roots, exact event groups, same-event pair recall, opposing-view and cross-language joins, abstentions, related-result utility, and arrival-order/restart stability. Use a precision-first selection rule fixed on train/validation. Zero false joins on a small holdout is necessary but not sufficient; report confidence bounds and review every error against the adjudicated event boundary. Require a meaningful gain over unchanged body-E5 and strict baselines without any hard-negative mixed group in the predeclared critical slices. The owner must set the operational false-route risk target before activation.
4. Only after independent real cross-publisher validation and scale evidence, prepare the exact live policy, affected Source/Topic diff, source-root migration and rollback, retention/model-rights analysis, Trust review, and actual Chrome/service QA for the separate ADR-064 owner activation decision. Until then, improve related visibility while hard same-story admission remains conservative.
