## Reproduced findings and corrections

1. **Multiline contributions rejected.** A root with `First paragraph\nSecond
   paragraph` returned `invalid`. Body validation now allows CR/LF/tab while
   retaining the 8,000-unit limit and rejection of unsafe controls. Titles/IDs
   retain their stricter validation. The same body rules apply to stored revisions.
2. **Successfully stored discussion becomes unreadable.** Creating 130 roots of
   8,000 ASCII characters produced a 1,065,419-byte view; the GET handler returned
   500 at its 1 MiB response cap. Both adapters now check the actual discussion
   projection before committing mutations. Growth over the cap returns capacity
   (413), retains the prior version/text, and leaves reads and withdrawal usable.
   Pagination remains future work; no silent truncation or higher response limit.
3. **Version transition invariants were not enforced by repositories.** Both
   accepted `save` with unchanged revision 0. A repeated generation factory let
   reset reuse generation/revision and accept a pre-reset command. A shared
   contract now requires exactly the next revision for save, and a different
   generation with revision 0 for reset, in addition to the existing expected-
   version comparison. Memory also enforces the existing 8 MiB snapshot budget.
4. **First initialization was not atomic.** Schema creation and initial insert
   were separate transactions. A serialization/insert failure could leave an
   empty table that required manual recovery. Initialization now uses one
   transaction; the regression verifies a failed first write can be retried.
   Database opening/transaction-start errors are also normalized.
5. **Application mutations returned full internal state.** Although the HTTP
   handler already projected it, service callers received all vectors/revisions.
   Command results now contain only version and generated IDs; reset returns only
   version. HTTP response shapes are preserved. Purged revisions/author fields
   are checked in both repositories, not just hidden in the display projection.

- Generate cryptographically random process tokens and IDs/generations that stay
  distinct across restarts; deterministic ID factories are for tests only.

  rather than fall back to another port. The present handler accepts an already
  bounded in-process request; it does not provide socket protections itself.

  trusted composition/test dependencies, never API parameters.

  invalidation, then test actual pairing and CRUD across popup/service restarts.
- Review the new transport/permission diff and run the approved loopback/browser

  certify listener code or browser interoperability that does not exist yet.
