# Synthetic normalized SQLite dry run

This isolated experiment does not import production modules, open the owner database, alter existing Topic assignments, or migrate retained state. Run with Node 24:

From the repository root: `node --import ./spikes/topic-resolution/harness/deny-external-capabilities.js --test --test-isolation=none apps/local-service/experiments/topic-cloud/sqlite/prototype.test.js`

The prototype accepts only a new `topic-cloud-synthetic.sqlite` file in a `topic-cloud-synthetic-*` directory under the OS temp directory. Tests make a unique directory per run and remove it after closing SQLite. Foreign keys, strict tables, and transactions are enabled. A batch with a bad edge rolls back; discussion and contribution IDs stay unchanged while edge scores change. The edge table stores each undirected candidate once and has indexes for both endpoint queries. Per-side indexed top-N scans are merged into a bounded result. Source pagination uses an indexed creation order. The test seeds 140 Sources and vectors, so the current PoC's 100-Source cap is absent here.

This is mechanics evidence only. JSON vectors are easy to inspect but inefficient for high-dimensional production storage; the experiment does not benchmark exact vector scan, index recall, WAL/concurrent readers, storage growth, or real E5 semantics. It does not define deletion/withdrawal lifecycle, schema migration from the production JSON row, API pagination contract, retention policy, or historical source lineage. ADR-023's source-anchored whole reply trees, legacy pins, and Forget/withdrawal provenance rules require a specific migration and lifecycle design; this schema's simple immutable identity is only one invariant. ADR-016's no owner-data backup/export boundary remains in force: this experiment makes no owner backup or persistent export. A separately reviewed migration and explicit owner-data/security approval are required before any retained database is opened or converted. No graph edge asserts Topic identity or moves posts.
