# ADR143 current-producer transfer — code only, no phase executed

Pure metadata/arithmetic/profile helpers and a prospective root-only fitter are
implemented. There is no fitted artifact, source freeze, target capture, encoding
or application runtime import. The fitter's explicit mode is not execution approval.
Read [ADR143](../../../../../decisions/ADR-143-current-producer-transfer-gate.md)
and the top of STATUS/HANDOFF before continuing. ADR142 is closed and immutable.

The five new fitter files are under root review; no real fit or final capture
is authorized by their presence. The separately frozen DEV controls
completed once with4/4 inputs per producer and verified cleanup; this establishes
instrumentation compatibility, not semantic quality. The32 final labels are now
sealed after that proof, before any final collection. Current source-only helpers
and the prospective driver are not imported by the application.

`fit.js` is inert without the explicit supervised mode and root-created source
freeze. It imports the pinned offline-capability guard even for an actual fit,
denying network/DNS/subprocess/provider paths. Its fixed readers reuse only the
127 TRAIN and48 CAL metadata/vectors with exact byte pins; old final bodies,
vectors and outcomes are not read. The three declared fits and CAL selection
publish a selection receipt last. Disabled selected cuts publish no admission
receipt. The separate Win32 supervisor owns the Node Job and bounded artifacts;
fixed source/input bytes are rechecked before publication. Target producer hashes
also require the final collector's stable source files before any fitter freeze.

`producer-profiles.js` adds a pure, fixed eleven-source construction recipe for
the two actual target producers. It excludes the model selection receipt and
collector freeze to avoid a circular hash. Both bind the computed profiles
separately. This is a file-identity recipe, not proof of runtime authenticity,
native document authority, freshness or rights. Its three invented-input tests
cover source sensitivity, distinct producers and rejecting unlisted/hostile claims.

Before source freeze, independent collector review identified that host allowlisting
alone did not authorize each external resource's robots/TDM/response policy. The
final prototype is consequently Document-only: it blocks all external subresources,
but inline scripts may still execute. The pinned reader observes this restricted
single-document DOM, not an ordinary fully loaded dynamic user page. Both numeric
producer gates remain, but neither their conjunction nor a browser pass establishes
ordinary dynamic-browser transfer. The actual static producer can be assessed
separately. Richer resource instrumentation requires its own prospective version.

`methods.js` implements the declared three-weight CAL selection, conservative
max128 work bounds and paired root-only descriptive accounting. It does not fit,
score or capture pages and cannot attest supplied input identities. Its assessment
requires32 distinct article groups, two per root, with ordered producer results.
Distinct groups do not establish statistical independence; that claim is false.
Each producer keeps all32 rows, including unavailable inputs, and must independently
meet24 accepted/zero wrong/at least one accepted per root. Producer views are not
64 independent articles, agreement is not correctness, and neither producer can
rescue the other's missing input. Terminal child/OOD quality is not evaluated.
Conditional-on-available counts are separate. The future runner still must bind
actual producer/encoding receipts and exact refusal reasons and independently
audit saved CAL scores, membership, zero-error and minimum20-group invariants;
the pure selector and supplied hash-shaped identities establish none of those.

Prospective upper bounds are17,602,992 fitter units,1,818,624 fusion-coordinate
visits,884,736 CAL plus393,216 target coordinate products,64,256 rank units and
128 final encoder calls. They exclude all CPU/native instructions, hash/copy work,
capture, E5 initialization, compilation, queue, DB and client latency. Actual work
and per-phase resources must be recorded by the future reviewed driver.
