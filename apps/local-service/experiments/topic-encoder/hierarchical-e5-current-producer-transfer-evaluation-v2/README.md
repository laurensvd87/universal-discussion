# ADR145 fixed-artifact reobservation: code-only evaluator v2

This namespace implements prospective pure contracts, signed-zero-preserving raw
E5 vector transport, a fixed-read manifest, local encoding/evaluation phases,
stored audit and owned-Win32-Job supervisor. No source freeze, real artifact
scoring, assets, capture, encoding or model execution has been performed here.
Defaults are inert. Root must review the complete code and write the approved
freeze; no CLI writes a freeze or automatically invokes another phase.

This is a NEW complete32-article reobservation, not an independent untouched
cohort. No old capture packet or vector is reused. The old successful fitter
proof and selected coefficients/fusion/numeric cuts remain unchanged; a distinct
reviewed artifact-reuse receipt binds their NEW producer profiles/transfer hash.
It does not rewrite the old selection receipt or claim the new profiles were
trained. Compilation checks the actual selected artifact bytes before any input
body is admitted; no fit, retune or classification occurs in reuse validation.

Actual current-static extraction and the restricted single-document DOM reader
remain separate producer scopes. The technical browser-current ID is not ordinary
dynamic-browser validation. All reports retain
ordinaryDynamicBrowserProducerValidated:false. Passing both small numeric gates
would not authorize browser/application cutover, native or canonical writes.

The metadata-first contract requires all16 fixed capture results and successful
drained supervisors before any input packet body is read. The manifest supplies
a private admission handle for the fixed paired packet reads. Each of8 fixed
batches contains4 article groups and at most8 producer rows/16 encoding calls.
At most128 field calls are permitted; even equal inputs are not reused. Both
fields must pass unchanged embedding inputText validation before either is
encoded. Empty/whitespace title and unsupported control characters remain explicit
encoding-unavailable, with no normalization, alternate producer or title-only
rescue. Capture availability and encoding availability are different observations.

The unchanged released v1 vector codec uses
current-producer-transfer-raw-e5-vectors/v1 under this NEW evaluator freeze.
Its JSON number grammar preserves binary64
and signed zero. Unit vectors and their bit hashes are rechecked; every vector
pair names the exact captured source/body/title hashes. Hashes are identity links,
not producer, freshness, rights, native-document or Source authority.

Stored verification recomputes full32-per-producer descriptive assessments,
conditional availability, per-root/language/host and paired counts. It binds
saved decisions to source/document/vector identities, but does not re-execute
classification or prove predictions were honestly generated by a model. Reports
say distinctArticleGroups:32 and statisticalIndependenceClaim:false, never64
independent observations. No child/OOD or population-precision claim follows.

Public ledger reads hard-refuse all retained input/vector packet keys. Private
completed saved-admission proof grants paired input reads; only metadata is readable
through the public ledger. Encoding-supervisor verification binds the exact
freeze-file SHA and source map, byte receipt/vector hashes, clean exit/drain,
wall limit and memory bound, not just success booleans.

The metadata-only capture handle does NOT grant packet reads. A second private
handle requires the saved capture-admission receipt AND its actual successful
admission supervisor: exact receipt bytes, evaluation freeze-file hash/source map,
clean exit/own-tree drain,1536MiB bounds and180s wall. Both proof files enter the
fixed ledger and Python's initial/end metadata hash checks. Fresh rechecks run
before each paired packet read. Encoding, evaluation and stored verification
all require this second gate; the explicit admission phase itself never reads
a packet. Invented reader/callback tests assert zero packet/encoder calls on
missing, failed, changed or drifting admission proof.

Result decisions use a new compact schema and retain original scorer schema,
transfer hash, witness and exact semantic/vector bindings. The unchanged full
scorer identity is stored once per report. A full64-decision fixture generated
by the actual private scorer on invented16-root geometric coefficients fits
below the unchanged262144-byte report cap. No actual fitted artifact is
opened by that test.

The manifest enumerates the collector's62 literal source/DEV-proof/reuse
keys plus this evaluator and reused pure modules; it never follows a path from
JSON. The root-written freeze schema is
current-producer-transfer-evaluation-freeze/v2. Fields, in chosen writer order:
schema,executionApproved:true,sourceHashes (exact exported SOURCE_KEYS),
protocolSha256,oldSelectionReceiptSha256,artifactReuseReceiptSha256,transferHash,
collectorFreezeSha256,encoderHash,inputHashes (exact11 fixed nonfreeze INPUT_KEYS
values),captureMetadataHashes (all32 literal new result/supervisor keys),
ordinaryDynamicBrowserProducerValidated:false,freezeHash. The final hash is
SHA256(JSON.stringify(the ordered object without freezeHash)). File-byte hashes
are kept distinct from the selected model's program-JSON modelJsonHash.
The source union currently has72 literal keys; the root writes this freeze ONLY
after all16 new captures and their successful supervisors exist and are reviewed.

After review, the explicit supervised schedule is:

    python supervise.py --admit-captures
    python supervise.py --encode-batch N
    python supervise.py --evaluate

N follows fixed1..8 order. Admission requires all16 capture result/supervisor
records before any input packet can be opened. Every encoder rechecks that gate
and the saved admission. All8 drained successful encoder receipts are required
before private vector-packet reads for evaluation. Existing output directories
and exclusive started/result files prohibit replay, including failed attempts.
No command above has been run. Python/default and JavaScript/import defaults
do not touch inputs or assets.

The supervisor enforces1536MiB RSS/private/Job commit,1GiB host physical/commit
reserve,C768MiB/D512MiB free, fresh retained D TEMP and1-thread local ORT. A Node
handshake follows successful own-Job assignment; no breakaway is allowed.
Child165s, supervisor active170s and final own-tree drain5s fit inside the
absolute180s wall, checked after final source/evidence verification. Resource
failure terminates only that own Job/exact child. Evidence is bounded512KiB per
phase, retained TEMP+output64MiB/1024 entries; nothing is recursively deleted.
The Windows guards are code-reviewed adaptations, NOT yet an executed proof for
this new namespace. No supervisor or actual model phase has run.

The stored-only command is `node verify.js --verify-stored`. It has no encoder,
model-compiler or classifier import, rereads only literal allowlisted evidence
after successful gates and checks fresh bytes before delivery. It does not
re-execute predictions or constitute native/runtime attestation.

Pure checks use invented metadata/text/axes only:

    node --test --test-isolation=none contracts.test.js

No private/owner Source input, provider, network, database, browser, E5 or old
final fixture is used by these tests. Earlier closed studies remain untouched.
