# Real-root input construction v3 - review before execution

V3 changes only experiment capture construction, not the learning method or gold.
V1 partial 2/96 and V2 partial 88/96 train/cal captures remain frozen diagnostic
evidence; neither model nor final-test phase ran. Never splice their prefixes,
reuse attempt markers or automatically retry. A fresh 96-article collection needs
explicit review and authorisation.

A root-reviewed Semantics diagnostic succeeded on the exact raw HTML hash that
previously failed. Its oversized attribute section contained quoted transport
metadata. The immutable lexical adapter removes only quoted data-mw/data-parsoid
attributes before BOTH unchanged extractors. Original/decoded/pruned identities,
removal counts and captured text hashes remain distinct and bound. This is not a
production parser change, arbitrary sanitization, wider policy permission or a
claim that every extraction failure is understood.

The existing byte-pinned Dutch Wikipedia robots adapter stays in its frozen V2
folder. Raw/decoded fingerprints, exact origin and full published DENY line must
match. Its space remains encoded as percent20; the rule is never dropped. This
does not claim that RFC rules require repair or change production robots behavior.

The same pinned 48 training/48 calibration/32 test articles, 16 root-only heads,
lambda 0.1, body/title 0.75/0.25 fusion, two capture views and CAL-only view selection
remain. Closed C weights, observed D detail policy and fixed C baseline are unchanged.
Only four independently verified partial specificity anchors receive child scores.
Original V1 manifest and pure assessor source bytes remain explicitly pinned.

Capture, result, selection, input-construction and supervisor namespaces are V3,
using ADR138 paths only. Construction hashes bind the V3 collector, unchanged V2
robots adapter, immutable metadata pruner, ADR138 wrapper/supervisor and unchanged
public fetch/robots/static-extraction code. Explicit path mappings cover each;
there is no old capture/receipt fallback. Model outputs and one-shot markers live
only here. MURMINGLE_REAL_ROOT_V3_SUPERVISED is the model supervisor sentinel.
Hidden own-child launch, one thread, heap/RSS/commit/reserve/wall/log guards remain.

Source creation authorises no phase. Run/supervisor defaults are inert.
Stored-only --verify-local requires complete existing evidence and recomputes
saved-decision arithmetic, never a classifier. There is no model/fetch/DB execution
in pure fixture tests, nor any quality-ready or activation claim.

This is purposive multilingual Wikipedia feasibility, not representative web
quality, a 98% gate, canonical assignment/provider authority or permission
to alter the running crawler.
