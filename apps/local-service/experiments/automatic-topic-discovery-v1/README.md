# Automatic named-topic discovery experiment

The harder real-news [method comparison](RESULTS.md) now shows that the first
four-article success is insufficient: paired-E5 complete-link merges17 wrong
event pairs, a threshold graph62. A separate compact sentence encoder also leaves
wrong/missed events. None is activated as event matching. The goal now requires
subject/event focus evidence and accurate common-scope names as well as geometry.

This unregistered pure module starts the owner's29October requirement: visits
must supply novel named topics/news, not merely populate a predefined taxonomy.
It loads no model/database, changes no registry and grants no assignment/posting
authority. The live20-node hierarchy and its running crawler are unchanged.

For a bounded64-document parent cohort in one declared E5 representation, compare
all2016 pairs once (774144 coordinate products/32768 matrix bytes). Incremental
chronological admission requires pairwise support with every group member, not
only one neighbor or a drifting centroid. Competing groups leave a new document
provisional. The supplied thresholds are experimental policy, not probabilities
or quality acceptance. Cohorts have deterministic ordering and explicit windows.

Each candidate automatically obtains a bounded representative-source headline
and its attribution, with no mandatory LLM.
For equally representative medoids, prefer a headline containing an explicit
year. That improves a title's context without treating the year as a publication
timestamp or choosing a less coherent page merely for its headline.
Repeated URLs, material and near-identical syndicated vectors do not multiply
support. Distinct publisher keys
are separate from document count; their producer must identify publishers rather
than counting Wikipedia language subdomains as independent publishers.

Subject and event cohorts are distinct. A recent visit is not a publication date;
events with unknown publication metadata remain provisional. The existing Source
contract does not retain that metadata, so ingestion changes and provenance are
still needed before a live event pipeline. The helper does not attest supplied
dates, publisher identities or the parent path itself.

The separate publication-claim normalizer now preserves calendar-day versus
timestamp precision, compares consistent timezone claims and refuses conflicts,
calendar rollovers, modified/visit time and unknown timezones. It has no clock or
IO and is not yet wired to capture or live Source storage. Bare dates never become
invented UTC midnight. A known UTC instant is usable even when its publisher-local
offset is unspecified; see [RFC9557](https://www.rfc-editor.org/info/rfc9557/).
The helper accepts bounded JSON data and never returns invalid raw field values.

The isolated-world DOM collector now reads bounded publication claims from the
current article. It ignores modified times, other URL-bound articles, author and
comment fields, and ambiguous unscoped article graphs. Nine actual offline Chrome
fixtures pass, including a page that overrides its own DOM methods. A separate
owned-response browser check verifies that HTTP CSP blocks executable page code
while publication JSON-LD remains readable. These prove native DOM behavior,
not the truth of a publisher's date or production Source attestation.

The closed metadata DEV runner fetched the four previously usable literal public
URLs again, with normal robots/TDM checks and all new outcomes retained. It hashes
the same allowed response before parsing it in offline Chrome, then saves only
normalized publication metadata and existing observation hashes, not full HTML.

Topic lifecycle must remain useful even before multi-source confirmation: an
eligible page can immediately offer its readable page-context title for a new
discussion; background grouping supplies a stable shared subject/event identity
only when supported. Show that concrete context before posting and keep existing
posts bound to it when labels or assignments later change. Global Search Topics
should emphasize supported topics with real human discussion. A provisional page
label is not evidence that unrelated articles belong to the same shared topic.

Next compare real same-event/different-event/novelty cases against other bounded
approaches. Include different news about the same entity, delayed arrivals,
syndication, singletons, multilingual captures and erased inputs. Calibrate on
development only, lock policy and test new subjects/sites/time. Existing consumed
root/child TEST cases cannot serve as fresh quality acceptance. Synthetic geometry
tests here establish algorithm behavior and work limits only.

Production needs a stable dynamic registry separate from fixed classifier heads,
exact current-Source commit fences, indexed bounded candidate retrieval, automatic
publication policy, erasure/prototype invalidation and unchanged original thread
destinations. Proposal keys are disposable evidence identities, not public topic
IDs. Do not reinstall the entire matcher or reclassify every page per news event.
Do not make human approval of every event a growth bottleneck. Preserve a clearly
named page-only discussion while background discovery is uncertain.
