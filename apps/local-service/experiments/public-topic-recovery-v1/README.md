# Recovering occupied topic identity from public discussions

General websites remain the primary matching path; no Wikipedia entity is
required. A discovered subject currently loses its Source-derived head when its
evidence changes or is erased. Its expressly posted name, opaque identity and
public discussions survive. Retaining a forgotten Source prototype to recover
that identity would violate that boundary.

This experiment compares three bounded approaches to recovering the existing
occupied topic using independent public evidence:

1. Exact normalized public caption alone.
2. E5 agreement with explicitly published caption/body, independent of wording.
3. Both literal agreement and public semantic evidence.

Each public candidate has an exact root/caption/body digest. Its encoder inputs
contain only that published caption and the first 2000 normalized characters of
the published body. No origin URL, Source digest, hidden accepted ancestor path
or Source prototype is copied into that input. The trusted encoder producer must
use the exact same paired representation as the current page cohort. The scorer
cannot attest that producer, an SQL transaction or actual embedding inference.
Changed public text or incompatible representation refuses, and a short generic
comment cannot provide semantic recovery evidence. Up to64 retrieved public
roots and64 fresh cohort members are allowed. Multiple roots of the same scope
are one candidate; distinct close scopes abstain. This only recommends an ID;
it does not publish a Source head, merge discussions, infer event equality or
grant posting authority.

The initial semantic floor is0.88 for **every** fresh member against a public
candidate, with0.03 separation from the next scope. Those development constants
are unvalidated. Comparing public discussion text against paired web content may
not provide enough separation; the actual comparison must report misses and
wrong sibling/sense matches, rather than interpreting a passing pure test as
accuracy. All three baselines remain visible, including unsafe literal-only
recommendations. No live/startup/profile18 activation is performed here.

The first closed offline comparison uses retained E5 material from the owner's
recipe/video and nine available non-Wikipedia animal/product pages. Public
discussion examples are invented and declared; they are not actual user posts
or a representative benchmark. Source/input hashes and unchanged end pins must
be retained. Only the existing packaged local encoder is allowed; no network,
LLM, database, crawler interruption or download is required. Earlier captures,
vectors and outcomes are immutable. A new output directory is exclusive.

The first attempted comparison (`ad829974`, output
`public-topic-recovery-dev-20261029`) failed at a mistakenly selected128MiB V8
heap limit after creating its empty output directory. No semantic comparisons
or public vectors were saved; the precise allocation site was not retained.
That source commit and empty output remain preserved. This is not evidence of
host memory exhaustion or semantic accuracy. Before correcting admission, Root
read the actual existing crawler6384 and worker11880 model command options: both
already use512MiB. The maintained runner now requires that exact established
packaged-model runtime, uses a distinct output namespace and emits phase
progress. This is a single separately decided comparison, not an automatic
budget ladder. The model/encoder code, all three strategies, constants, input
cohort, original native-SQL fixture limits and live settings remain unchanged.

If a strategy is promising, subsequent integration must capture public evidence
at its real SQL revision, invalidate it on body edit/root withdrawal, recheck
the public root and current Source fences in one canonical publication
transaction, retain established destinations, and unify legacy/static and
dynamic identities without treating equal labels as equality. Representative
quality, real browser/provider, bounded latency, migration/recovery and live
activation remain part of the full project goal.
