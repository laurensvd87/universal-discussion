# Owner-wide discussion depth for learned topics

Explicit, unregistered hierarchy18 editor composition. The deepest confident
page assignment is retained. A current editor can choose a broader ancestor
according to the same owner-wide policy row used for the fixed public taxonomy.
There is no personal slider, new classifier, embedding fit, model call, global
topic scan or search-index rebuild. Import/construction and ordinary startup do
not install or opt in to these functions.

`defaultMaxDepth` applies within each learned topic branch. A default of1 can
select Steam Deck, while2 can select Steam Deck OLED if that page already has
that supported leaf. Existing fixed taxonomy subtree rules provide a learned
branch default. A `subject-<opaque UUID>` override controls a particular learned
subtree: a niche subject can stay broad while a popular branch becomes specific.
Depth within the fixed taxonomy retains its existing absolute-path convention;
depth within learned subjects counts from the first learned subject. The most
specific matching named rule wins. No rule can extend the actual supported path.

An override cannot be written above its own current position. If a new parent
later attaches, the opaque rule follows its subject and is clamped to its new
position. A withdrawn subject may keep an opaque ID/depth rule; it retains no
erased name, prototype, Source material or hidden ancestry in the policy. The
existing public-evidence identity CAS remains responsible for any later recovery.

The wrapper reuses the original static policy verifier, expected-revision CAS,
limits and owner-only SQL permissions. Static and named rules commit in one
transaction with one policy revision. It updates only that small policy row,
not Sources, vectors, heads, member selections, roots, reply destinations or
watermarks. Ordinary MVCC readers see the prior committed policy during an owner
write and the new policy on their next read. Existing semantic read signatures
already include its revision, so users can refresh shared context without a new
model call or per-user preparation.

The grouped editor walks at most8 current heads. It checks current Source
membership for the selected ancestor before offering it as a posting scope;
otherwise it tries a supported broader ancestor, then the original page context.
The ordinary append/AI-root ports still validate the exact captured scope and
material. A policy change never moves an existing root, changes its chosen title
or invalidates an otherwise current captured broad draft. The existing ancestor
feeds aggregate narrower discussions under the general group without moving
canonical roots or their replies.

Search remains explicit navigation over confirmed topics and saved discussion
targets. A specific existing discussion remains searchable after the default
editor becomes broad. Navigation and replying to that existing thread are not a
personal grouping setting. The separate unification of legacy/fixed and named
search identities is still required; this component does not replace that work
with a page-dependent search or hide saved conversations behind the default cut.
