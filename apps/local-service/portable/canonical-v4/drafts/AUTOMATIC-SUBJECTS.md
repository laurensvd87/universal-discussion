# Provider-independent named subject storage

This is an unregistered hierarchy18 component. Do not install it on ordinary
startup or the live schema17 database. It has no dependency on the optional
Wikipedia registry. The maintained owned native fixture requires12 new cases
separately from the original25 semantic,8 metadata and10 Source-binding cases.
Adding those assertions is source work; only a completed actual run proves SQL.

The trusted worker runs the explicit fingerprinted v2 subject policy from
prepared Sources. The repository accepts that planner's original input and
recomputes proposals, rather than trusting a caller-provided publication plan.
SQL independently verifies generation, installed matcher/representation, current
Source version/receipt/stamp/postability, actual title witness, protected ancestor
context, candidate snapshot and identity/revision CAS. It does not independently
rerun JavaScript headline segmentation, E5 inference or the complete-link numeric
policy. The worker remains trusted for that computation, just as in stored
semantic preparation. App/crawler roles cannot publish or export prototypes.
This is not an attestation of original capture or event equality.

The IDs table contains opaque UUIDs and revisions only. Current heads contain
erasable labels, prototypes, broad accepted context and explicit named parents;
members contain protected Source witnesses. A selected named subject is derived
browsing metadata, never canonical posting or route authority. Source update,
receipt, embedding and stamp hooks withdraw genuinely changed/erased evidence.
Dependent named descendants withdraw too, including concurrent children via a
deferred cascading parent FK. Opaque identities and human records survive.

Unchanged-material renewals refresh version/operation fences atomically without
creating new topics. A partial renewal cannot pass the read's current witness
joins. A true withdrawal erases the matching key with the other derived data;
rediscovery does not recover that old UUID by retaining a forgotten name/hash.
Later integration with author-owned discussion context is needed to offer
existing occupied threads without treating erased Source metadata as public.

Existing heads keep their founding label/prototype/parent while adding evidence.
A small new cohort cannot continually move the center or delete assignments
from an earlier cohort. Updating labels/centers or reparenting is separate owner
maintenance; this component does not claim a completed adaptive hierarchy.
All named paths are limited to8 named levels, with the separately bounded static
ancestor context retained. No broad-root confidence is invented for unknowns.

The candidate port uses indexed exact focus/context scopes, at most128 scopes
and64 returned heads. It refuses an incomplete cohort. Publication serializes
overlapping focus scopes, rechecks their complete head snapshot and returns a
conflict after a concurrent new head; a caller retrieves candidates and replans.
There is no global catalog fit/scan or global named-topic writer lock. This port
does not yet implement ANN retrieval or multilingual aliases. Reads are ordinary
MVCC SELECTs with no row/advisory write locks or model work.

Remaining production work includes the complete schema18 manifest/roles and
readiness checks, bounded background cohort scheduling, occupied-topic indexed
search, exact author-selected context and immutable canonical routing, recovery,
real UI/crawler concurrency and live rollout. The older provider-specific10-case
Source extension remains separate and does not substitute for this general path.
