# Independent public discussion evidence

This is an unregistered hierarchy18 component. It is not installed by ordinary
startup, the dashboard or the crawler. Existing schema17 and all canonical
destinations remain unchanged. It is the next step after the public topic
recovery development comparison; indexed evidence alone does not reuse an ID,
merge discussions, classify a page or grant posting authority.

An explicitly published named root already owns a public caption and discussion
body. The input port reads its **current revision body** from revisions rather
than silently indexing the original payload after an edit. Its digest covers
only exact root ID, named scope ID, public caption and current public body. The
encoder sees the normalized caption and first2000 normalized body characters.
The transform, Unicode boundary rule and meaningful-word gate have a separately
pinned input contract. No hidden Source context, original URL, material digest,
Source embedding or erased Source name is retained in this index.

Foreground publication and edits append independent opaque-ID events. They do
not call a model, update a worker-owned hot counter or change the canonical
discussion. Two ready tasks per turn share the existing worker's serial encoder
queue. A current representative is reused without another model call; human
evidence takes priority over an agent representative. A short generic comment
is excluded. Each failed task receives its own five-second deferral so another
task in the bounded turn can progress. No extra encoder or scheduler is created.
The automatic subject coordinator accepts this maintenance port explicitly;
ordinary composition leaves it disabled until complete18 readiness and cutover.

There is one indexed prototype per generation/paired representation/published
scope, rather than a DISTINCT scan of every comment in a popular topic. Its
root-context foreign key removes it on withdrawal. A worker repair event walks
remaining explicit roots in16-row chunks if a representative disappears. A
public body edit immediately fails the lookup's current digest join, even before
background repair. Source erasure can change origin/version metadata without
changing the independently published meaning; the valid public vector remains
reusable. Same-representation classifier changes do not change that input space.
Incompatible representations do not match. A future representation transition
still requires explicit bounded rebuild/startup composition.

Lookup selects at most65 raw indexed representatives **before** joining current
public text and identity revisions, and refuses if the raw cohort exceeds64.
It must not hide a competing scope just below the similarity floor or claim a
complete candidate cohort after silently truncating it. The typed port rechecks
public digests, representation, input contract, focus keys, vector shape and
unique identities. Normal app/crawler roles cannot access it; the worker has
execute-only tasks, repair, defer, store and candidates ports. No role receives
direct table access or a new public HTTP capability.

Encoding finishes before the short SQL store transaction. SQL locks root,
context, event and then prototype, skipping a contended public root. It never
holds Source, discussion, named-head or feed-clock locks. It rechecks the exact
current text/version, active model, generation and protected paired weights
before storing. The trusted worker performs E5 and word/focus computation;
these are not independently attested by SQL. Getter/proxy boundaries refuse
without invoking hooks, and closing maintenance joins physical work while
leaving the shared resource's lifetime to its owner.
