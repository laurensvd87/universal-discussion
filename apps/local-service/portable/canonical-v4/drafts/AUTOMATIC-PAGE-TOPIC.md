# Captured page discussions joining later subjects

This unregistered hierarchy18 component depends on named feeds and the public
read/reply bridge. Existing startup, crawler and live data remain unchanged.
No capture, embedding inference or provider call is introduced here.

A future page-scoped root captures its protected Source material digest in the
same canonical transaction that creates the root and immutable posted caption.
The existing authored finalizer already holds and validates that Source. The
constant-sized trigger adds no discovery, head or shared clock lock. There is
deliberately no backfill from the current Source into older page discussions.
Both human roots and explicitly published AI roots use this capture path.

When a preferred subject later appears, its independent context event repairs
the page's original root cohort using the existing16-row bound and frozen upper
ordinal. Each root can join the subject and confirmed named ancestors only if
its captured digest exactly matches the current protected Source receipt and
all current member/version/stamp/model fences. The actual named path is locked
with the existing ordered shared SKIP LOCKED check. Contention defers derived
work and leaves the direct page feed and posting available.

Root IDs, canonical destinations, posted scope, captions and bodies never move.
An identical-material Source renewal remains eligible. A changed Source cannot
reassign the old discussion to its new subject, even if it has the same URL and
very similar embedding. Source erasure deletes the private material witness
and derived head/edge witnesses; the expressly published page thread remains.
Historical page roots without a protected capture remain available directly;
their material cannot be invented from today's page.

Search activity has an independent edge-backed witness. A derived subject
label stays Source-backed and never gains a manufactured author-caption
reference merely because a page discussion appears under it. The directory
uses activity to rank human-occupied subjects while the caption's provenance
remains honest. Activity deletion atomically removes its directory pointer and
enqueues opaque-ID-only repair. Stable edges are updated by difference, so
reindexing cannot repeatedly destroy its own activity witness and create an
endless repair cycle. Foreground posts do not update activity counters.

The new scope-repair core is an exact predecessor except that its bounded
enumeration walks actual feed members, including derived page roots. The public
worker wrapper now lets context events run this same core. Search is the exact
predecessor except for using activity rather than caption ownership to report
occupation and displaying the matching caption alias. A search for an older
page title must not return an unrelated newer title merely because the URL was
reused. All old reply/body/evidence/replay checks remain unchanged.

Ten additional owned-native reports are required by both completion validators
in addition to all original100. They cover no-backfill, human/AI capture,
delayed subject publication, same-material renewal, first-parent aggregation,
different-material refusal, physical lock contention, activity withdrawal,
quiescent reindexing, roles and erasure. Pure source tests do not prove these
SQL assertions have executed.
