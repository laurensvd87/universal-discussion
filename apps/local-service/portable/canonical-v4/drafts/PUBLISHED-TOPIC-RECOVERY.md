# Public identity recovery during named-topic publication

Unregistered hierarchy18 composition, not a live migration or startup opt-in.
The ordinary general-web planner still discovers labels from current, distinct
page material with complete cohort cohesion. The independent public index can
then restore a withdrawn subject's opaque ID, instead of manufacturing another
discussion topic for the same current meaning. Source erasure never leaves a
hidden name, vector, focus key or ancestor path as a recovery index.

The repository explicitly accepts the public evidence port. It retrieves at
most64 current public representatives for the proposed focus keys and runs the
typed recovery planner before calling the same atomic named publisher. Every
new member must score at least0.88 against the independently encoded public
meaning. The winner needs a0.03 margin over every other compatible public scope,
including competitors below0.88. Matching the name alone is insufficient.
An ambiguous narrow topic falls back to an already-supported parent in the same
plan, then to the page context if no such parent is proved.

Existing resolved heads keep their original revision-checked publication path.
This composition restores only an absent head with a surviving opaque identity
and a current, explicitly published root. It never merges two existing public
IDs or silently reparents a current head. An unresolved active public head
prevents a duplicate proposal rather than being overwritten. Static/dynamic
aliases, single-page lookup and owner-specific depth composition are separate
integration work. The subsequent [single-page lookup](SINGLE-SOURCE-TOPIC-MATCH.md)
is now implemented and separately validated in an owned140-report run; it remains
an explicit opt-in.

The command carries public root IDs, exact current public digest, root version,
identity revision and the complete bounded candidate snapshot. SQL locks current
Source witnesses and identity rows first. Focus guards fence prototype changes;
root/context/prototype reads use SKIP LOCKED so an ongoing human edit produces
a conflict rather than a row/guard deadlock. The same-focus index is bounded
before joining roots. New prototype writers serialize only overlapping focus
keys, not the entire registry. Normal human posts append their existing events
and do not acquire the prototype guard.

SQL rereads the current public candidate set and exact identity revisions. It
recomputes paired vectors from protected semantic inputs and compares each
Source/prototype pair once, at most64x64x384 coordinate products, independent of
overlapping proposals. Caller-supplied scores or forged worker coordinates
cannot restore a public identity. The publisher increments the opaque identity
revision and creates a new current Source-derived head/members atomically.
Existing canonical root IDs, captions, bodies and destinations stay unchanged.
Public evidence is transient input; no new private Source material is retained.
