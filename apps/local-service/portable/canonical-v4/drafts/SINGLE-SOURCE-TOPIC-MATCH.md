# Fast assignment of one prepared page

Unregistered hierarchy18 worker composition. It is not installed by ordinary
startup and does not activate the new matcher. It assigns a current protected
page to an existing named subject; it creates no identity and changes no public
caption, canonical destination, root, reply or owner setting. Subject discovery
still requires distinct supporting page material. Looking up an already known
subject does not require a second new page or another encoder invocation.

The worker reads the current protected Source title/witness, normalizes NFKC and
enumerates complete contiguous word phrases of up to8 words and80 title units.
At most64 words yield fewer than512 distinct focus probes. All probes fit the
new512-key SQL input bound; the existing128-neighbour/64-cohort discovery bounds
are unchanged. Longer/unsupported workloads refuse as a whole instead of hiding
a competing phrase. No language vocabulary, stemming, guessed synonyms, LLM or
Wikipedia dependency is added. Aliases and cross-language synonyms remain work.

SQL locks current Source preparation using SKIP LOCKED and checks its exact
title/version/operation/material/stamp and active generation/model. At most65 raw
indexed literal heads are read. More than64 refuses. An indexed parent walk adds
only ancestors, at most64 total heads and depth8, with no descendant/catalog scan.
The function locks those heads in one order using SHARE SKIP LOCKED, checks all
captured revisions/parents and rereads the complete literal candidate IDs. A
changed or busy cohort returns busy. It does not take a global registry writer
lock. An entirely new topic can commit after the last cohort read; this is a
point-in-time derived assignment, and subsequent discovery can refine it.

The current protected paired E5 body/title values are fused once. Up to64 exact
binary64 prototype dot products are computed. A candidate needs0.88 similarity
and a0.03 margin over every incomparable branch, including below-floor rivals.
Ancestors and descendants do not compete as separate senses. The deepest
confident candidate wins even if its parent has a higher score. Close siblings
can fall back to their confident common parent. Without a confident candidate,
the ordinary page context remains usable; no new name is manufactured.

Only that Source's selected membership and ancestor memberships are inserted.
The popular subject's head/identity is not rewritten, so different Sources can
be assigned concurrently using compatible shared head locks. Existing identical
memberships return retained without writes. Source change/erasure uses existing
invalidation, removing the affected derived heads/memberships; public discussions
remain independent. SQL functions are execute-only for the existing worker role.
App/crawler roles have no internal matching or vector capability.

The existing coordinator accepts this repository explicitly. It matches directly
after an index task, before neighbourhood discovery, and rechecks after broader
publication so a still-confident leaf is restored. A busy final match leaves the
existing durable discovery request pending. Closing joins physical work and
does not acknowledge a later completion. There is no second queue/model/timer.

Seven guarded focus/repository tests and three additional coordinator cases
cover complete probes, Unicode, bounds, typed witnesses/results, failure privacy,
early assignment, busy backoff and shutdown. Ten new mandatory native reports
exercise actual worker SQL, most-specific/parent fallback, no row churn, stale
Source refusal, capacity, held writers, concurrent reads/posting/two different
Source assignments, production coordinator ordering and real Source change.
Those reports use invented titles/vectors and explicitly owner-controlled
adversarial head setup. The updated owned SQL execution is pending. Neither this
component nor these fixtures prove representative semantic quality, cross-language
recall, many-user load, foreground/provider/browser behavior or live latency.
